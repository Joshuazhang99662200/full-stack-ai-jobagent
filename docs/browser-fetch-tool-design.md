# 本地浏览器定向抓取工具设计

状态：暂缓，尚未实现或注册。2026-10-20。先完成 [后端诊断](browser-control-diagnosis-2026-10-20.md)，不把设计稿当作底层故障已解决。

## 目标与事实边界

提供一个可由智能体调用的定向抓取接口，显式绑定用户现有的招聘标签页，区分连接成功、页面读取成功和完整 JD 抓取成功。首版只覆盖 BOSS 的岗位搜索与读取，不触发联系、投递或简历修改。

当前事实：Windows Computer Use 在读取 Chrome 状态时返回 URL 核验失败并终止；已试浏览器通道未返回用户截图中的招聘标签页。原因尚未查明。新工具不能承诺解决底层连接故障，也不能替代或跳过现有工具的安全核验。底层拒绝操作时，首版直接报告阻断，不切换其他控制后端重试。

## 方案选择

| 方案 | 效果与代价 | 选择 |
|---|---|---|
| 在宿主支持的浏览器接口上增加明确的绑定与抓取接口 | 复用已有访问检查，消除静默换窗口、重复导航和结果误报；仍依赖底层连接可用 | 推荐 |
| 人在页面导出内容，再由本地工具校验导入 | 不需要浏览器控制，能保全来源；搜索和导出仍由人完成 | 独立备选，不自动切换 |
| 修复现有 Windows Computer Use 的 URL 识别 | 可能恢复原始鼠标操作；运行时由宿主维护，本仓库不能修改其校验策略 | 向工具维护方定位，不自行替换 |

## 调用接口

以下名称是拟议接口，不是本会话已具备的工具。

```text
jobagent_browser.inspect()
  -> 当前宿主通道、实际返回的标签页摘要、阻断原因

jobagent_browser.bind(browser_id, tab_id, source="boss")
  -> 用户确认的具体标签页 + 本次绑定编号

jobagent_browser.observe(binding_id)
  -> 当前 URL 校验结果、页面类型、读取时间、可见正文证据

jobagent_browser.search(binding_id, query, location="上海", limit=3)
  -> 实际页面上的岗位列表；只提交一次搜索

jobagent_browser.fetch(binding_id, observation_id, listing_id)
  -> 完整 SourceJobRecord，或明确的失败状态

jobagent_browser.release(binding_id)
  -> 释放工具绑定；保留用户原有标签页
```

`bind` 不接受自行拼造的 tab_id。候选标签页必须来自宿主本次实际返回的列表，用户要能根据标题和不含令牌的网址确认目标。绑定包含 browser_id、tab_id、来源与本次会话身份，不保存 Cookie、密码或网页会话令牌。

`search` 和 `fetch` 的实现只调用宿主当前支持且已授权的浏览器接口。不给模型通用鼠标坐标、任意 JavaScript、任意导航或底层调试端口入口。该限制不改变宿主访问检查。

## 执行流程

```text
用户指定本地现有标签页
    |
宿主实际返回此标签页？ -- 否 --> UNBOUND，停止
    |
   是
    |
绑定 browser_id + tab_id + source
    |
底层允许访问且当前 URL 可核验？ -- 否 --> BLOCKED，停止
    |
   是
    |
读取可见页面；核对域名、页面类型与停止标志
    |
    +-- 登录 / 验证 / 风控 --> USER_INTERVENTION_REQUIRED
    |
    +-- 搜索页 --> 检查读取额度 --> 提交一次搜索
    |                             |
    |                     从实际结果生成 listing_id
    |                             |
    +-- 详情页 <----- 只允许打开该次观测中的详情链接
            |
       读取标题、公司、地点、薪资及 JD 正文
            |
       完整性校验 -- 失败 --> INCOMPLETE，不能入库为完整 JD
            |
           成功
            |
       SourceJobRecord + 页面证据引用
            |
       私有文件 --> 既有 jobs import-observations
            |
       既有 jobs triage --> 待人选择的岗位清单
```

首版默认一页搜索结果、最多三个新岗位详情。读取预算和翻页间隔消费现有来源清单及账本，达到限制就返回部分结果与原因。已有岗位与已联系岗位按现有记录标识，不重复打开详情来扩大抓取量。此工具不生成或发送招呼。

## URL、页面身份与停止行为

- 每次操作前从绑定通道取得当前 URL。只接受 HTTPS 和来源清单允许的域名、路径；解析 URL 后比较主机名，不能用字符串包含判断来源。
- 无法读取或核验 URL 就停止。不接受模型自行声称的地址、历史截图或用户粘贴地址作为当前页面身份的替代证据。
- 每次观测生成 observation_id，绑定实际页面、读取时间和内容摘要。页面发生导航后旧观测失效，旧 listing_id 不能用于新页面。
- 接口不暴露 reload。相同搜索已在当前页时直接读取，不再次提交；任务恢复时先 observe，不重跑搜索。
- 搜索超时不自动重试。只有底层仍允许访问时才做一次只读状态核对；底层明确终止后，本次工具调用立即结束。
- 命中来源清单的停止标志，就结束该站本次任务。更换标签页、账号、浏览器或控制后端都不能作为自动恢复手段。
- 正常用户交接只报告已观测事实，不自动输入登录信息或操作验证页面。

## 结果与诚实汇报

统一结果包含 status、stage、binding_id、observation_id、captured_at、completed_steps、records、missing_fields 和 blocker。只在成功读取页面后生成页面证据引用；只在完整契约通过后输出 records。

| status | 可以报告什么 |
|---|---|
| UNBOUND | 找不到可绑定的用户目标页，未接管 |
| BLOCKED | 底层访问检查拒绝或无法核验页面身份，未执行后续操作 |
| USER_INTERVENTION_REQUIRED | 已读取明确的登录、验证或风控提示，并交人 |
| INCOMPLETE | 只读到部分字段，明确缺项；不能说已取到完整 JD |
| SUCCESS | 对应阶段完成；列表成功不代表详情成功，详情成功不代表入库成功 |

示例：`status=BLOCKED, stage=observe, completed_steps=["inspect", "bind"], records=[]` 只能报告“已绑定，页面读取被阻断”。不能报告“工具可用、正在抓取”或将底层超时归因为网站风控。

## 与仓库的边界

新建绑定、观测与结果契约放在 `src/jobagent/schemas/browser_fetch.py`，岗位字段直接引用既有 `SourceJobRecord` / `JobListing`，不复制类型。领域层只处理已验证观测与抓取状态，不依赖浏览器 SDK、DOM、Typer 或 SQLite。浏览器实现留在宿主适配层，页面提取规则按来源清单加载。

抓取输出、完整 JD 和本地去重资料只保存在 `candidate/private/` 或 `.jobagent/`。通用诊断日志只记阶段、错误码与不含秘密的来源标识。网址中的查询参数、Cookie、令牌和完整招聘方聊天不进入通用日志。

既有 `jobs import-observations` 负责入库校验；`jobs triage` 负责硬过滤与匹配。此工具不调用 outreach、conversations 发送命令或 applications 投递接口，不变更任何审批。

## 验收与接入

1. 离线先验证：空列表、错误标签页、URL 缺失、域名仿冒、过期观测、导航变化、停止标志、预算耗尽、重复搜索、正文截断。
2. 用宿主测试替身证明：底层拒绝后没有任何输入、重试或后端切换；observe 不刷新页面；搜索最多提交一次。
3. 契约校验覆盖 JD 原文完整性、必填字段、列表与详情混用、以及所有结果状态的汇报边界。
4. 宿主安装并显式注册后，先在本地合成页面实测；再由用户选定一个已登录标签页，完成一次观察、一次搜索和一个完整 JD 的小样本验收。遇平台停止条件就交人。
5. 更新能力目录时，只有实际存在且可调用的入口才能标已落地。源码实现、宿主注册、目标页连接和真实抓取成功分别验收，不能相互代替。
