## 结论

原版交代了证据与审批边界，合成内容也有明确标识。这些信息保留。主要问题是视觉材料太抽象：同一套圆角卡片和箭头重复三次，读者很难据此看出这个 Python 包究竟返回什么。

| 优先级 | 位置 | Hallmark 对应规则 | 改法 |
|---|---|---|---|
| 高 | `docs/assets/career-harness/hero.svg:13`、`:27`、`:34`、`:41`，以及 `evidence.svg:6`、`approval.svg:7` | 54、67：标题前的惯例标签、大写与字距 | 去掉装饰英文和序号，标题直接说明正在展示的程序行为 |
| 高 | 原版三张图整体 | 84，以及 47c 的真实性判断：有实际产品时应展示它 | 从合成 fixture 运行真实 CLI、复核函数、diff 与摘要校验，排版实际输出；不画一个尚不存在的网页界面 |
| 中 | `hero.svg:18`，原版 `README.md:7`、`:11` | 63、69：圆点连接的元信息，以及同一主张重复出现 | 删除口号和三段式元信息；导航改成普通链接，数据以代码本身的字段呈现 |
| 中 | 原版首屏、证据图和审批图 | 8、9：构图与节奏重复 | 三图分别使用 CLI 记录、文本 diff、摘要核对表，内容本身决定版式 |
| 中 | 原版大外框、彩色标签与图标组合 | 3、F5、F7：模板式卡片与装饰性容器 | 取消装饰图标、点阵与柔和大圆角，用字级、行距和分隔线组织信息 |

以上是对 SVG 和文案的人工判断，不能冒充网页 linter 自动给出的结果。README 由 GitHub 渲染，不受本仓库 CSS 控制；网页首屏高度、表单交互等规则不直接套用到 Markdown。

## 材料与事实

- 岗位：`jobagent jobs fetch alpha-001 --source mock` 的实际 JSON，来源为仓库内置的合成 fixture。
- 证据与复核：使用 `tests/optimizer/test_verification.py` 和 `test_review.py` 的合成数据；复核结论由测试夹具提供，不能称为真实模型独立审查。
- diff：实际调用 `ResumeDiffBuilder.build`，不由模型叙述差异。
- 审批：只对合成 `ApplicationPackage` 运行摘要函数和 `verify_approval_is_current`；修改正文后捕获真实 `STALE_APPROVAL`。
- 不使用真实候选人资料、不调用招聘平台、不用测试中的合成答复作为真实发送授权。

## 验收结果

- Hallmark V2 官方 `sloplint --scope component --render` 检查三份配图源文件，最终结果为 0 FAIL、0 REFLEX、0 WARN。截图档位包含 1280、1440、1920px 首屏，以及 1440、375px 全页。
- 独立 fresh-context 复核发现：把桌面 PNG 直接缩到手机，会让文字过小。已增加 375px 单列导出，并通过 `<picture>` 切换；桌面图注从 16px 调整为 18px。复核者对这一项的确认结果为 `resolved`。
- 另用本地 Markdown 预览实测 1120px、390px 浏览器宽度：三组图片均加载成功，桌面与手机分别选中对应文件，无页面横向溢出。这不是已部署 GitHub 页面的截图。
- 全套 Python 测试 1033 项通过；Ruff、严格 mypy 与 diff 格式检查通过。未改变领域逻辑、审批逻辑或平台操作。
- 所有显示的数据都可追到 `samples.json`。没有真实模型评审、真实平台回执、访谈评价或效果指标。

原版的完整流程关系更容易一眼看全；新版优先展示实际程序返回值。README 的能力表与架构段继续承担全流程说明，不再把流程反复绘制成卡片。
