# 交给 Muse：记忆飞轮实验的资料字段表

请按本模板整理一份 `memory-experiment-dataset-2026-11-02.md`，放在用户私有目录。本页保留实验启动前的资料采集格式，不代表实验当前进度；已完成的受控实验及限制见 [原型验证说明](unified-memory-validation-2026-11-03.md)。资料整理本身不启动模型或实验。

这是资料收集格式，不是新增 API 或 SQL 契约。Muse 先从已有记录整理，不用部署代码、改数据库或新发招聘消息。不能为凑齐表格补造历史原话、批准、编辑或结果。

## 填写约定

- “必填”表示这一栏要出现；找不到就写“未记录”，读不了写“未读取”，任务不涉及写“不适用”，不要混用，也不把未知填成零。
- 事实和本人选择尽量附原文及可回查位置。宿主总结、代理判断、模拟材料分别标明，不冒充本人原话。
- 公司、岗位、候选人可用稳定代号；同一对象在所有案例中使用同一个代号。原件留在私有区，不含凭证、Cookie 或令牌。
- **整份 MD 只交给协调方和评测侧。记忆代理不接收原件、预期答案、打分理由或验证集历史反馈。** 实验前再拆出可学习资料和逐次评测输入；一份文件分章节不构成访问隔离。
- 岗位、写作和运营记录都可收集，不限定产品经理或某一行业。有多少真实材料先交多少，不为达到样本数补写。

## 一、整批资料填写一次

| 字段 | 要求 | Muse 填什么 |
|---|---|---|
| 资料版本 | 必填 | 本次整理的版本与整理日期；后续修改保留旧版 |
| 用户代号 | 必填 | 稳定的候选人代号；不同用户不可混成同一个人 |
| 覆盖范围 | 必填 | 哪段时间、哪些任务和渠道；哪些记录尚未读到或无法取得 |
| 共同背景 | 必填 | 当时已确认、允许用于这些任务的履历事实、目标和限制；附版本及出处，不从后来的结果反推 |
| 已生效偏好与参数 | 有则填 | 用户已经确认的条件、写作偏好及搜索预算；原值、适用范围、版本与来源。缺失如实写，不重新向用户询问数字 |
| 来源目录 | 必填 | 使用了哪些文件、聊天或数据库记录；可回查位置、读取日期；已有摘要可附上 |
| 分区清单 | 必填 | 各案例属于“可学习历史”“封存验证”或“待分配”；已有划分直接保留，没有划分时先写待分配 |

“共同背景”是任务当时就允许知道的资料，不包含验证题答案。把本人后来的选择塞进共同背景，也会泄露答案。

## 二、每个案例都填写

一个案例对应一次真实任务或一次明确反馈。用下面的字段表逐条记录，不要把所有岗位压成一段总结。

| 字段 | 要求 | Muse 填什么 |
|---|---|---|
| 案例编号 | 必填 | 唯一且稳定的编号，例如 `CASE_001` |
| 关联分组 | 必填 | 用户、岗位、联系轮次、同一篇稿件或简历的关联编号；用于识别重复与防止跨集泄露 |
| 所属分区 | 必填 | 可学习历史／封存验证／待分配 |
| 任务类型 | 必填 | 搜索、岗位判断、招呼语、回复、简历、运营分析等；收集到不代表当前代码已支持 |
| 时间顺序 | 必填 | 任务发生时间、反馈发生时间、记录入库时间分别填写，含时区；只有先后关系或批次时间就保留该精度 |
| 当时的请求 | 必填 | 本人给 Agent 的原始任务要求；没有原话时标明是宿主转述 |
| 当时可见的输入 | 必填 | 任务开始前实际取得的背景、JD、候选岗位、消息或材料；不能补进后来才知道的信息 |
| Agent 当时的产出 | 有则填 | 实际搜索结果及排序、草稿或文件内容。初稿、改稿、实际发送稿分别保存，不用摘要代替全文 |
| 本人反馈 | 有则填 | 准确原话、实际改稿及发生时间；同时注明对岗位、文案、事实、规则还是发送作出的决定 |
| 来源与证据等级 | 必填 | 原始消息／本人实际编辑／界面决定记录／宿主转述／代理推断／合成案例，并附可回查引用 |
| 后续结果 | 有则填 | 真实观察到的发送、回复、面试等结果与观察时间、依据；未知继续写未知 |
| 缺失或争议 | 必填 | 哪段原文、时间、来源或关联缺失；是否存在前后矛盾，不替用户裁决 |

“接受文案”“喜欢岗位”“批准发送”“实际发送”分别填写。一项有记录，不推导其余三项。

## 三、按任务补充内容

| 任务 | 需要的具体材料 | 用于验证什么 |
|---|---|---|
| 搜索／岗位判断 | 当时的查询词、渠道、已生效预算；实际候选岗位集合及顺序；各岗位 JD 原文与完整／部分／未取得标记；本人选中或拒绝的岗位及原话 | 是否学到了真实方向偏好；是否把薪资、地区、文案意见错误扩成行业黑名单。候选集合缺失时不能计算完整排序表现 |
| 招呼语／回复 | 已确认事实；原始 JD 或对方消息；准确初稿、历次实际改稿、本人反馈、准确已发稿（如有）；改写者是本人还是 Agent | 文风和事实修正是否被记住；系统重生成不算本人编辑；不能用未来的改稿作为本次输入 |
| 简历 | 当时的确认事实、JD、原始简历、实际定向版本及本人修改；文件位置、版本；在线简历或附件类型 | 是否保留事实和版本，是否无依据补写经历。统一在线简历不记作逐岗 PDF |
| 运营分析 | 观察窗口及截止时间；实际事件明细和关联岗位／轮次；对应规则或文案版本；已知分子、分母及纳入／排除项；未观察到与真实零值分别标明 | 重复计数、观察窗口、未知结果和不同渠道口径能否正确处理；样本不足时不宣称改善或因果关系 |

长正文可用代码块原样附在该案例后。真实文件也可留在原位置并提供本地路径；只有路径、无读取权限时标明“未读取”，不能视为内容已交付。

## 四、每个案例的评测答案单独填写（仅评测侧可见）

这些内容允许缺失。没有本人判断的题，先标“待制定评测标准”，不能让 Muse 凭想象填出“本人一定喜欢”。评测代理后续可以根据已授权的样本制定标准，但必须注明这是代理标准。

| 字段 | 要求 | Muse 填什么 |
|---|---|---|
| 参考判断 | 有则填 | 本人当时认为好／不好／更偏好哪版／尚未决定；岗位偏好与文案评价分开 |
| 为什么好或不好 | 有则填 | 本人给出的理由、改动和引用；宿主或代理解释必须单独标注 |
| 必须满足的点 | 有则填 | 本人明确要求保留的事实、表达、条件或行为；原文来源 |
| 不能出现的点 | 有则填 | 明确禁止的事实捏造、失效偏好、未经批准的动作等；原文来源 |
| 可接受的变化 | 有则填 | 多种表达或合理搜索方向；没有唯一正确措辞时不要硬设标准答案 |
| 应当怎样使用记忆 | 有则填 | 该反馈只用于这一个岗位、这类任务或长期偏好；何时生效，是否已撤回／取代。未知就写未知 |
| 判断来源与状态 | 必填 | 本人原始判断／本人确认的标准／评测代理拟定／未知；现有版本与出处，不能仅写“已确认” |

在评测代理看到记忆侧输出之前，固定这一轮的评分标准和版本。封存验证的预期答案和打分理由不能作为轮间反馈回流给记忆代理；如要用一批题反馈学习，应预先把它归入可学习历史，另留封存验证题。

## 五、已有异常案例单独列出

有真实记录就附，没有就写“暂无”，由实验阶段另外生成并明确标为合成。不要在生产数据中制造这些问题。

| 异常类型 | 需要附的记录 |
|---|---|
| 重复或乱序 | 同一事件重复出现、同编号不同内容、反馈晚到；保留原编号与实际顺序 |
| 偏好变化 | 前一次选择、后一次撤回或纠正及原话；不能只交最终结论 |
| 范围误用 | 单岗意见被扩成全局、岗位意见被当文风、文案接受被当发送批准的实际例子 |
| 资料不完整 | JD 截断、本人原话缺失、来源失效、版本变化、时间未知等 |
| 恢复问题 | 中断点、恢复后发生了什么、重复处理或保存失败的真实回执 |
| 跨人或外部指令 | 已有的候选人混淆、JD／消息夹带指令等案例；没有则不编造真实事故 |

## 六、同一份 MD 的组织顺序

```text
1. 整批资料说明与共同背景
2. 案例索引（编号、分组、分区、任务类型、来源等级、主要缺失）
3. 可学习历史：逐个案例的输入、产出、实际反馈与来源
4. 封存验证：逐个案例的题目输入
5. 评测侧专用：按案例编号保存参考判断、理由和使用范围
6. 异常案例与缺失清单
```

请同时检查：同一岗位任务的初稿、修改稿和重复导入不能拆到学习集与封存验证两边。同一事实在不同文件出现，仍只算一个来源事件。同岗位的后续新任务如用于跨轮恢复实验，须明确列出时间截断和测试目的，单独报告，不冒充新岗位泛化测试。

## 可直接发给 Muse 的提示词

> 请按这份字段表整理 `memory-experiment-dataset-2026-11-02.md`，保存到我的私有工作区。优先读取已有真实任务与反馈，不新造样本、不改生产库、不重新询问已确认的参数。保留原始输入、实际产出、本人原话和真实修改；找不到的栏位注明未记录、未读取或不适用。宿主总结与本人原话分开，Agent 重生成不算本人编辑。建立稳定编号和关联分组，保留已有数据划分；未划分的写待分配。评测答案集中放在评测侧专用章节，整份文档只交协调方和评测侧，不能交给记忆代理。同一任务的不同版本与重复记录保持同组。这里只整理资料，不运行双 Agent 实验，不把原始数据上传公共仓库。交付时列明实际收集了什么、还缺什么即可，不另写架构概述。
