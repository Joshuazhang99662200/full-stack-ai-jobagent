# 给 Muse：岗位详情弹窗按最后一张参考图重排

请先在 Muse 宿主中修改二级弹窗，并一并修正岗位列表中间的进展栏。本次不改仓库前端代码。

主表后续按 [五列布局与 LLM 进展说明](muse-five-column-progress-2026-11-01.md) 调整。本文的列表措辞表作为表达示例，Muse 可按真实上下文自由改写，不机械套用。

二级弹窗默认展示和折叠方式按后续的 [弹窗精简要求](muse-five-column-progress-2026-11-01.md#七二级弹窗再精简先看要紧的其他按需展开) 执行。下文列出需保留的内容，不再要求所有分组默认展开；先呈现当前材料和操作，历史按需查看。

这次要参考的是最后一张图的**内容、字段和分组方式**：打开岗位就能看到职位要求、当前招呼语、历史材料及沟通情况。不要继续把运行摘要、技术日志和原始数据作为弹窗主体。只参考内容结构，不恢复绿色配色；保留现在的白底、浅灰、浅蓝，以及本人待办的小红点。

## 列表中间的进展栏也一起改

截图里“已保存的工作：写招呼语、评估匹配度；是否已联系招聘方：目前没有足够记录确认”这一整段，用户要读完才能猜到发生了什么。不要继续把工作清单、联系情况和缺数据的说明拼成一句话。

列名简化为“进展”。每个岗位先放一句最有用的事实，最多再加一行确实已安排的下一步。细节留给弹窗，主表不展示内部活动名称和空字段说明。

### 按实际情况直接使用这些说法

| 查到的真实情况 | 中间“进展”栏直接写 | 右侧本人待办 |
|---|---|---|
| 已找回招呼语全文，确实等待本人审阅，尚未发送 | 招呼语写好了，还没有发送。 | 红点 + “看看招呼语” |
| 已选定这版文案，但还没有本人发送批准 | 文案已选好，还没确认发送。 | 确实已发起逐项审批且材料齐全时，红点 + “审阅发送内容” |
| 已获有效批准，尚未执行 | 材料已批准，还没有发送。 | 不自动再问一遍；确需本人另行触发执行时，提供含义明确的入口 |
| 招呼语已核实发出，但没核实是否查看 | 招呼语已发出。 | 只有其他真实待办才显示红点 |
| 已核实对方看过招呼语，目前没有回复 | 对方看过了，还没有回复。 | 不因等对方回复就显示红点 |
| 对方发来问题，尚未处理 | 对方有新消息，还没有回复。 | 红点 + “看看对方的消息” |
| 对方明确索要简历，尚未准备好 | 对方想看简历，材料还没准备好。 | 先由宿主准备；确实需要本人补充信息时，才列出具体问题 |
| 简历成品已准备好，确实等待本人审阅 | 简历准备好了，还没有发送。 | 红点 + “看看简历” |
| 简历已核实发出，尚未收到反馈 | 简历已发出，还没有收到反馈。 | 只有其他真实待办才显示红点 |
| 只有岗位评估记录，其他材料或沟通还未核实 | 已经评估过这个岗位，后续进展还没查清。 | 宿主先核对，不默认显示“看看招呼语” |
| 仅缺少联系记录，无法判断是否发过消息 | 有没有联系过对方，还没查清。 | 宿主先查历史记录，不把未知当成未发送 |
| 本人已决定暂缓 | 这个岗位先放一放。 | 没有新的本人待办就不显示红点 |
| 已有关闭或放弃的业务记录 | 这个岗位已结束。 | 详情保留具体原因与历史；不自动重新推进 |

以上每句话都要由该岗位的真实记录支持。尚未找到全文时，不能因为一条“起草已完成”的工作记录就显示“招呼语写好了”，更不能给一个点开后没有内容的“看看招呼语”。有已发事实时，优先显示发送或沟通进展，不因旧稿还在而倒退成“待你看稿”。同岗若还有其他未处理事项，在右侧单独说明。

### 第二行只写有用的下一步

已保存的计划可以改写成容易理解的短句，例如确有相应计划时写“接下来准备定向简历。”。不要自行补出计划，也不要把尚未执行的事写成已经在做。

没有安排下一步时，主表不再给每个岗位重复占一行“还没安排下一步”。这条信息留在详情里说明。没有近期执行更新也不在每行重复一遍；如果确实影响当前判断，用上表的未知提示说明即可。

同一行不要连续出现“已有评估”“匹配已完成”“已评估匹配度”等同义内容。岗位适合的具体理由、旧版本和完整工作过程放在详情中，列表只保留帮助本人判断下一步的信息。

### 主表和待办必须对得上

- 中间说“招呼语写好了”，右侧“看看招呼语”就必须能打开本岗的准确全文。
- 中间只说“已经评估过这个岗位”，右侧不能无依据要求审阅不存在或尚未找回的招呼语。
- 中间说“对方有新消息”，点开就直达对应消息和拟回复；不跳到工作日志。
- 多条记录冲突时，先显示“进展还需要核实”，由宿主核对，不能同时声称“已发出”和“等待首次发送”。
- 顶部“等你看看”的数量要按核对后的真实待办重新统计。缺记录、无下一步或只有评估结果，都不能单独成为本人待办。

不要为了让每一行都有红点，就给所有岗位套同一个动作。改完后抽查不同情况的岗位，逐一确认中间的进展、右侧的动作和打开后的实际内容一致。

## 打开后，按这个顺序显示

### 1. 岗位信息

最上方显示岗位名称，下面用一两行放公司、渠道、工作地点和薪资，再提供“打开原岗位”链接。当前业务进展用一句话说明，例如有记录支持时写“招呼语已发出”。不把“匹配评估已完成”当成岗位已投递。

| 显示名称 | 要展示的内容 | 没有记录时 |
|---|---|---|
| 岗位 | 岗位全名，允许换行，不截掉关键方向 | 写“岗位名称待核实” |
| 公司 | 来源中保存的公司名称；原来源匿名就保持匿名 | 写“公司名称待核实”，不猜真实雇主 |
| 渠道 | BOSS、智联或猎聘等真实来源 | 写“来源待核实” |
| 工作地点 | 来源中保存的城市、办公方式 | 写“工作地点还没核实” |
| 薪资 | 招聘信息中的范围和发薪月数，保留原意 | 写“招聘信息暂未提供薪资”仅限已核实未提供；尚未读取则写“薪资还没核实” |
| 打开原岗位 | 本岗可用的原始链接 | 无链接就不显示按钮，不放假链接 |
| 职位说明 | 已核实取得全文时写“已获取完整职位说明”；只读到摘要时写“目前只有职位摘要” | 写“职位说明还没核实”，不能凭摘要或完整标记推断全文已保存 |

弹窗应始终对应刚才点击的岗位，不再让本人通过另一个下拉框重新找一遍。若保留切换岗位功能，切换后标题、材料、消息和待办必须一起更新，不能串岗。

### 2. 职位要求与需要核实的地方

直接显示两个小分组：

- **职位要求**：把原 JD 的主要要求按条列出，可以点“查看完整职位说明”读全文。
- **还需要核实**：只列具体的不确定点，例如雇主是否匿名、办公方式未说明、关键要求是否满足。没有这类问题时不用占一个空分组。

“为什么考虑这个岗位”可用一两句说明与本人经历的联系，并能查看所依据的经历。不要只给匹配分数，更不要显示计算公式、加权过程、内部判断码。本人已确认的条件继续复用，不每个岗位重复询问。

### 3. 招呼语

适用渠道直接展示**当前拟发送的完整招呼语**，像最后一张图一样能在本弹窗中读完，不用去其他页面或队列找。正文较长时允许区域内滚动或展开，不以摘要替代全文。

- 标题写“准备发送的招呼语”；只有已保存草稿时才显示正文。
- 草稿可编辑时，按钮写“保存修改”。保存后生成新版本，旧版本继续保留；编辑不自动发送、不自动批准。
- 只读草稿可提供“帮我改一下”，由宿主接收修改意见，保存新稿后回到这里查看。
- 没找到草稿时写“还没找到这份岗位的招呼语”，由宿主先找回旧稿；需要重新起草时明确标成新稿。
- 猎聘等不适用招呼的渠道不显示这块，也不显示对应按钮；改为展示本岗适用的投递材料。

### 4. 目前进展

保留参考图里的“目前进展”分组，默认展开。只回答三件事：

| 标签 | 写什么 |
|---|---|
| 目前进展 | 最后确认的业务结果，例如“简历已发出，还没有收到反馈。” |
| 接下来 | 已安排的下一步；确实没有安排时写“还没安排下一步。” |
| 请你决定 | 具体问题和处理入口；若无本人待办则写“暂时没有需要你处理的事。”，未查全时不能这样断言 |

若从红点进入，具体待办优先放在弹窗顶部，直接给问题、依据和可用选项；不要求本人滚到最下方才找到操作。普通点岗进入则保持上述阅读顺序。

“有没有联系过招聘方”依据真实联系记录判断。不确定就写“有没有联系过招聘方，还需要核实。”，不能一边显示缺记录，一边肯定已经联系。

### 5. 招呼与简历：以前的材料也要能看

保留一个明显的“招呼与简历”分组，默认展开。里面按以下顺序显示，当前草稿不再重复粘贴一遍：

| 小分组 | 必须展示的内容 |
|---|---|
| 实际发出的招呼语 | 每次真正发出的准确全文、发送时间及接收方；有多次就分开列。不要用当前草稿替代已发内容。 |
| 以前的版本 | 每份旧稿、修改稿的可读版本名和已保存时间。点开即可看到全文；没有时间就写“时间未保存”，不从版本串猜日期。 |
| 简历 | 当前拟用的简历和历史成品，显示可读版本名，能预览或打开实际文件。 |
| 实际发出的简历 | 实际附件及版本、发送时间和对应岗位，不能用“简历已准备”代替。 |

只有本人统一在线简历、没有本岗定制简历时，明确写“这个岗位使用统一在线简历，没有单独保存定制版。”，前提是记录确实支持。文件引用存在但文件打不开时，写“之前的简历暂时打不开。”；没有找到文件与没有做过简历分开说。

作废稿不混在当前可用稿里；仍可在历史中查看，并标“已作废”。不要将作废稿重新用于投递。

### 6. 投递安排与结果

保留独立折叠分组，标题写“投递安排与结果”，默认收起；存在待本人处理的投递事项时展开。显示本次准备投什么、准备用哪份招呼语和简历、是否获得逐项批准、实际有没有执行、执行结果是什么。

计划和结果分别写清，例如“材料准备好了，还没有投递。”与“简历已发出。”不能合并成一个“已完成”。结果不明时写“还不能确定是否发出，先核实结果。”，不能催本人重复点击发送。

### 7. 沟通记录

保留独立折叠分组，标题写“沟通记录”。有未处理的新问题时显示红点，默认展开该消息；其余历史可按时间查看。

每条消息显示发送方、原文、已保存的真实时间和相关附件。先让本人看懂招聘方说了什么，再展示拟回复。摘要可以保留，但必须能在这里读到原文。没有消息、尚未读取、读取失败要分别说明，不能统一写“暂无沟通”。

### 8. 我的决定

对应参考图的“本人决定与批准记录”，标题可简化为“我的决定”，默认收起。保留本人对岗位的选择、对文案的意见、逐项发送批准及后续修改。

每条记录写清“决定了什么、针对哪份材料、何时决定”。接受文案不等于批准发送；批准发送不等于已经发送。展示本人原话或原记录入口，不只显示一个“接受”。

### 9. 做过的事与工作流程

将工作记录放在材料、投递和沟通之后，分组标题写“做过的事”，默认收起。用“写好了招呼语”“改过一版简历”“核对了投递结果”等具体记录，点开能看到对应产物，不铺技术日志。

弹窗底部保留 workflow：已完成蓝色，未开始或未记录灰色，当前步骤标“现在”。允许同岗并行；不能按流程顺序推断前面全部完成，也不反复显示整段进展摘要。

## 底部操作按当前情况显示

此处列的是动作含义，不要求在普通详情底部展示整组按钮及说明。后续以 [弹窗精简与审核视图要求](muse-five-column-progress-2026-11-01.md#七二级弹窗再精简先看要紧的其他按需展开) 为准：文案审阅、修改及批准进入专门审核视图，上方先放 JD 要点与关键词；岗位暂缓、放弃移到适用的岗位操作入口。按钮下的内部机制说明不显示给用户，能删而不影响理解的副标题全部删除。

补充意见按需展开，不常驻空输入框。保存意见或决定时一起保留；关闭弹窗不能让已输入的长文无提示丢失。

按钮直接说动作，避免“接受原稿”“接受 JD”“确定”这类含义不清的名称：

| 当前要做的事 | 按钮文字 | 点击后的含义 |
|---|---|---|
| 只确认喜欢这版文案 | 这版文案可以 | 记录文案意见，不批准发送 |
| 要求调整招呼语 | 帮我改一下 | 提交修改意见并准备新稿，旧稿保留 |
| 暂时不处理本次查看 | 右上角“关闭”按钮 | 仅关闭，不记录暂缓或放弃；不再提供重复的“先放一放”按钮 |
| 明确决定不再考虑 | 放弃这个岗位 | 说明这次决定的影响，按已接通的业务服务保存，不能只把卡片隐藏 |
| 逐项审阅材料后批准 | 批准这份材料 | 绑定当前准确全文及实际附件，交由既有审批流程核验；不自动发送 |
| 已有有效批准且允许执行 | 发送这份已批准材料 | 单独通过发送前校验，再执行并核对结果 |

不是每岗都显示整排按钮。根据渠道、待办和实际服务能力，只显示适用操作；主要按钮优先回答当前问题。操作尚未接通时禁用并说明“这里还不能保存选择，请在对话里告诉我”，且对话处理方式确实可用。保存成功才提示“记下了”，未成功不消除红点。

## 这些内容从普通弹窗中移除

前两张图红框中的内容不再出现在普通详情：匹配计算串、原始评估对象、SQL、字段名、队列路径、内部状态码、大段数据来源、运行编号、恢复点、执行者空值和原始 JSON。

也移除默认导航中的“原始记录”，不把“查看本次运行”当成用户必须点的下一步。完整排查记录继续留在私有环境，用户主动进入“更多 → 排查问题”时再查看。普通详情仍保留岗位原文、材料全文和消息原文，这些不能一起藏起来。

## Muse 修改后这样交付

1. 从原列表点进一个岗位，直接看到本岗信息、职位要求和当前招呼语，而非另一份技术摘要。
2. 展开“招呼与简历”，能找到实际已发全文、以前的版本和实际简历文件。不能以“见队列”代替。
3. 打开“投递安排与结果”“沟通记录”“我的决定”，可以核对相互对应的事实；没有的数据明确说明原因，不事后补造。
4. 从红点进入时直接看到具体问题和选项，操作后能核实保存结果；不能误发消息或简历。
5. 切换岗位、关闭再打开后，内容不串岗，历史不丢，工作流程仍在。
6. 给出宿主实际面板的修订结果及未接通事项。本说明本身不代表已完成 Muse 修改或业务接入；不要为验收试发招聘消息。
7. 回到主表，抽查已发出、待审阅、收到新消息及记录待核实等不同岗位，进展都是简短的具体事实，右侧待办能打开对应内容，没有全表复用的长段兜底话。

文案与红点规则沿用 [红点和待办说明](muse-panel-action-feedback-2026-11-01.md)，历史恢复沿用 [材料和历史记录清单](muse-panel-correction-2026-11-01.md)。本文件进一步确定二级弹窗的字段、顺序与展开方式，不覆盖已有审批、证据和隐私要求。
