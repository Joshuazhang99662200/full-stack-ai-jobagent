# 发给 Muse：统一记忆系统接线资料清单与提示词

这是接入资料的整理模板。实际来源尚未核对时使用；已有资料先核对并复用，不在每次任务中重新索要整套文件。这个阶段不改真实数据库结构、不重新配置本人偏好，也不执行招聘发送。

## 先返回这三份

| 文件 | 必须回答的问题 |
|---|---|
| `runtime-capabilities.md` | 当前真正读取的仓库、分支及 commit SHA；Muse 私有持久目录；Python/CLI/工具调用是否可用；模型如何调用；当前候选人标识；文件写入后能否读回、跨会话恢复是否实际验证。每项分别标“已验证 / 未验证 / 不可用”，附安全的验证回执。 |
| `data-source-map.md` | 实际数据库及版本、相关表和字段、队列/历史/稿件/消息文件在哪里；哪一份是岗位当前态；岗位、联系轮次、草稿、批准、发送及消息怎样关联；缺失时间和旧状态是什么意思；哪些程序在写入。给脱敏结构和保持关联的少量样例，不交整库。 |
| `feedback-records.md` | 本人喜欢或拒绝岗位、接受或修改文案、批准发送、确认长期规则分别怎么记录；事件编号、本人原话引用、发生时间及岗位关联是否存在；能否保留改前/改后全文；重复、撤回和中断怎么处理。分别给实际核对数量与无法读取的范围。 |

三份资料齐后即可核对基础契约；缺一项也如实返回已知部分，不为凑齐编造环境、事件、时间或接口。

## 对应阶段再补这四份

| 文件 | 需要的内容 |
|---|---|
| `artifact-lineage.md` | JD 全文、初稿、修改稿、获批稿、实际已发稿和简历文件的版本、摘要及关联方式；哪些文件确实能打开，哪些仅剩引用。 |
| `generation-calls.md` | 一次实际搜索/起草是怎样启动的；读过哪些偏好或规则；怎样送入模型；实际请求与产物是否有绑定证据；独立复核如何执行。缺历史输入就说明，不能重造一次来冒充。 |
| `metrics-baseline.md` | 当前每个运营比率的含义、分子分母、时间范围、岗位/联系轮次口径、来源、文案/简历版本及未知项。尚在等回复的样本怎样处理；只有计数而没正式统计也要说明。 |
| `recovery-and-acceptance.md` | 运行与恢复入口、并发控制、重复事件、中断恢复及实际回执；是否已连续两轮读回同一私有状态。已验证与仅有设计分开。 |

真实私有资料留在 Muse 的用户工作区。给代码维护者的是脱敏文件和必要样例，保留相互关联，但去掉姓名、联系方式、简历全文、消息私密内容及凭证。

## 可直接复制给 Muse 的 Prompt

下面整段直接发送即可。提示词自身已说明所需工作，不要求 Muse 先读到本机尚未推送的方案文件。

```text
我要把现有求职流程接入统一记忆系统，支持搜索偏好改进、文案改进和运营转化分析。请先做真实来源盘点，返回接线资料；这一步不改前端，不重写数据库结构，不迁移真实库，不发送招聘消息。

不要泛泛回答“可以实现”或“已经接通”。先读你实际能访问的环境与私有记录，把核对结果写成 Markdown 文件。

第一批必须返回三个文件：

1. runtime-capabilities.md
写明实际仓库/分支/commit SHA、私有持久目录、当前候选人标识、Python或工具能力、模型调用方式、私有文件写入/读回及跨会话恢复的实际验证情况。每项标明已验证、未验证或不可用，并给安全的验证依据。没有核实的环境不能按常识补齐。

2. data-source-map.md
列出真实数据源和权威关系：数据库版本、相关表结构、队列与历史文件、草稿与消息保存位置。说明岗位、联系轮次、JD、草稿、本人决定、批准、实际发送、回复如何关联，缺失时间如何表示，旧状态如何解释，哪些程序会写入。给脱敏结构及少量可相互关联的样例，无法关联或尚未适配的内容明确列出。

3. feedback-records.md
说明岗位喜欢/拒绝、文案接受/修改、发送批准、长期规则确认分别记录在哪里。核对事件编号、本人原话引用、真实时间、岗位和轮次关联、修改前后全文是否保存；说明重复、撤回和中断怎样处理。核对得到的数量与未读取范围分开，没读到不等于零条。文案接受不能当成岗位喜欢或发送批准。

后续按实际可读取情况补充四个文件：
- artifact-lineage.md：JD、招呼语各版、实际已发文本、获批材料和简历文件的真实版本及关联，哪些能打开。
- generation-calls.md：真实搜索/起草入口、读取的记忆与规则、送入模型的上下文、实际请求与产物关联、独立复核方式。只有规则文件却没注入，也要如实说明。
- metrics-baseline.md：实际比率的业务定义、分子分母、时间范围、去重口径、渠道及材料版本、未知和等待中样本。尚无正式统计就写尚无，不现场编数字。
- recovery-and-acceptance.md：并发、中断、重复事件和跨会话恢复的现状及真实回执，未实跑部分不要写成已验证。

操作边界：
- 数据库盘点用只读连接；确认不会写库的查询才可执行。有些现有 JobAgent CLI 会在打开库时自动迁移，不能因为命令叫 list/status 就直接对真实库试跑。未知版本不迁移。
- 可以在私有临时目录做小型文件写入/读回验证，不触碰业务文件；无法验证跨会话时直接记未验证。
- 复用已有本人配置，不重新询问初始化参数，不改变搜索额度、审批规则、当前任务或定时设置。
- 不调用尚未落地的 jobagent memory 命令，不安装或运行来历不明的接线代码；只记录现有真实能力。
- 不补造历史原话、批准、发送、读取和模型调用；学习摘要、consumed标记及模型自己的“已采用”都不算实际消费证据。
- 真实简历、联系方式、Cookie、Token和整库留在私有区。对外返回脱敏结构与样例，不能上传公共仓库。脱敏后仍需保留样例间的关联，并明确哪些为合成示例。

最终回复：
A. 三个首批文件的可交付文件或可读取链接；只能在你私有环境访问的路径要明确说明。
B. 已补齐的其他文件；未补齐的说明原因。
C. 一张汇总：资料项 / 是否实际读取 / 当前结论 / 缺口。
D. 优先指出阻碍接线的三个问题，不先改结构去迁就方案。

这些是给代码维护者的接线资料，不要显示在普通求职面板里。不要为了验证而试发招聘消息。
```

## 收到资料后怎么继续

代码侧先对照现有契约核对首批三项，决定需要适配的是字段、调用链还是持久化；再推进统一服务的搜索/招呼语消费和使用回执。后续材料支撑运营分析与恢复验收。

Muse 返回的文档也是待核对资料，不是自动生效的规则或批准。仅凭它写“已验证”不直接认定真实接入，须检查对应回执；资料缺失保留缺口，不把宿主问题变成用户重新填写整套配置。

总体分工与实施阶段见 [统一记忆闭环方案](unified-memory-muse-plan-2026-11-01.md)。
