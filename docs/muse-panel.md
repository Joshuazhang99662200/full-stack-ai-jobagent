# 宿主岗位面板

这是 Muse 岗位面板的当前展示与交互要求，合并了此前多轮修订。实现以所用仓库版本及已确认用户配置为准，适用于各岗位方向。React 组件可参考或复用；真实业务仍需宿主适配、持久化和回读。合成演示可运行不证明 Muse 或招聘渠道已经接通。

## 列表与入口

一行一个岗位，不按运行编号拆行，不展示公共分钟时间轴。同岗多轮工作和并行活动保留各自记录。

| 列 | 显示什么 |
|---|---|
| 岗位 | 岗位全名和公司；关键方向可以换行 |
| 渠道 | 实际来源，如 BOSS、智联、猎聘；作为本岗的能力路由 |
| 匹配情况 | 已保存的核对结论及具体理由；可靠分数可作次要信息，缺评估不补零或满分 |
| 进展 | LLM 根据本岗事实写目前的结果、等待、阻碍或已安排的下一步 |
| 待你处理 | 确需本人决定或操作时显示红点和具体动作，其他情况保持安静 |

默认按已有匹配度降序，可在列表左上角切换“按入库时间”，使用真实首次入库时间从新到旧排列。缺值排在相应分组后面，已放弃或关闭岗位沉底；同分时保持稳定顺序。排序只改展示，刷新数据和关闭详情后保留选择，不重新匹配或补造时间。

点击行内的岗位、公司、渠道、匹配、进展或留白，打开同一岗位详情。红点、原岗位链接和其他独立按钮执行自己的动作，避免事件冒泡重复打开；选择或复制文字不应误触。键盘入口、焦点恢复和移动端阅读也须可用。

默认 Muse 页面的视觉以同版本 `MuseCurrentApp.tsx`、`current.css`、`theme.css` 及[模板来源说明](muse-source-template-2026-11-02.md)为准；`?template=zip` 保留来源对照。仅 `?legacy=1` 的兼容 Console 沿用 [styles.css](../frontend/src/styles.css) 的白、灰、浅蓝样式。本文约束共同的业务展示与交互，不覆盖当前 Muse 的设计，也不恢复已废弃的旧模板。红点表示本人待办，红色用于“放弃岗位”。

## 进展由 Agent 根据事实写

用一两句说明眼下最有用的信息，事情复杂时可以多写，不设固定话术白名单或通用岗位偏好。已完成的事与新阻碍可以同时说：

- 已核实简历发出，并确认还在等回复：“简历已发出，等 HR 回复。”
- 本次访问确实跳到登录页：“BOSS 需要重新登录，暂时查不到新消息。”
- 只取得摘要：“完整职位说明还没读到，暂时没法核对全部要求。”
- 缺少发送回读：“发送结果还没核实，先查清，避免重复发送。”

示例只能在证据支持时使用。没有回读不等于未发送，没有读到消息不等于对方未回复。草稿、文案接受、材料批准、执行尝试和已核实发送分别表述，摘要不能改写业务状态、分数或统计。只有已有真实计划时才写下一步，不给每行重复填空。

SQL、取数及加权公式、字段名、内部编号、路径、摘要和模板串留在主动打开的排查入口。日常视图保留岗位要求、准确材料、消息原文和可读版本；删除不影响理解的副标题、重复摘要及空分组。

## 红点点开就能处理

红点来自已核实的本人待办，不表示未读或系统异常。Agent 缺记录、未查全、登录受阻或状态叫 REVIEW，本身不构成本人待办；先找出真正需要决定的问题。

点开后直接给出具体问题、相关事实、可用选项和操作结果，必要的准确材料放在同一视图。按钮用明确动词，不只写“确定”。普通打开或关闭不清除红点；保存并回读成功后才更新，同岗还有待办就继续保留。未知提交先核验，不能反复点写或乐观显示成功。

未接通的操作禁用并说明缺口；不得用只改卡片颜色的按钮冒充业务处理。需要用户登录时，宿主按实际渠道能力提供恢复入口；异常不伪装成本人必须作岗位取舍。

## 二级详情按条目读

右上角保持“关闭”。岗位、公司、渠道、地点、薪资、原岗位链接及职位要求分成容易扫读的条目，不挤成一个长句，也不藏掉影响当前决定的信息。

打开后先给一句进展和最相关的材料或问题，其他已有内容按需展开。信息只说一次；没有历史内容不铺一排空标题。保留“补充意见”入口，不必常驻空表单。关闭只结束查看，不保存决定、不改状态；有未保存编辑时须妥善保留或提示。

“放弃岗位”直接外显为红色按钮，不放在“更多”里；删除冗余“先放一放”，暂不处理时关闭即可。放弃必须保存真实业务决定并重新查询，不能只在前端把行沉底。

### 招呼语与审阅

| 内容状态 | 展示方式 |
|---|---|
| 拟发送 | 已保存的准确全文放在可编辑文本框，修改保存为新版本 |
| 实际已发送 | 使用正向回读所绑定的实际文本，灰色斜体、无文本框，不覆盖成当前草稿 |

业务发送情况未知时明确保留未知，不能为了套两种样式伪造已发或未发。文案新旧版本和历次实际发送分别可查。

招呼语的接受、修改及适用批准放在审阅视图。上方先呈现从本岗实际 JD 提炼的要点和关键词，再显示准确全文、附件及适用操作；缺全文或附件打不开时保持限制。普通详情不重复摆整组审阅按钮和机制说明，点待审红点可直接进入对应材料。

BOSS、智联按已接通能力展示招呼；猎聘路由隐藏不适用的招呼步骤、拟稿和按钮，未知渠道不默认开放。原始源中已有的历史文本仍保留供核对，不能据此声称该渠道支持发送。

### 历史和材料必须能找到

按候选人、岗位及联系轮次可靠关联，保留：

- 历版招呼语全文、简历成品和真实附件，当前与历史版本分别可打开。
- 拟投递安排、本人决定与准确批准，及其所指正文、附件和版本。
- 实际发送文本、实际附件、渠道结果及核验依据。
- 双方沟通原文、附件、真实时间，以及工作、失败和恢复记录。

已有记录先读回，不用重新生成的稿件冒充历史；不以“全文见队列”、路径或原始 JSON 代替用户可读材料。分别说明未记录、未读取、未接入、打不开及无法关联，不补造时间或批准。

### 底部工作流程

保留紧凑节点：已有完成记录用蓝色，未开始或缺少记录用灰色，当前步骤描边并标“现在”。“未记录”不等于未开始；心跳过期为状态未确认，失败和等待分别保留。同岗允许并行、重做或跳步，不根据九态位置补造前置完成。

只显示短节点与必要状态，不在每岗下面重复颜色图例、执行原理和整段进展。节点完成不代替本人批准或发送回读，运行取消也不自动关闭岗位。

## 同步、选择与重新撰写

选择须按候选人和联系轮次隔离，并由宿主持久化；全选、反选和清空只作用于当前可见范围。快速执行只消费已有的准确材料批准，不自动批准。已核实执行成功后才移出选择；失败、结果未知、被排除及用户重新选中的项目分别保留其结果，不能因批次结束一并清掉。

明确失败的项目经用户触发才可重试；结果未知时先核验。重新撰写须由宿主 AI 读取本岗事实与反馈，保留准确的修改前后稿和依据，使旧批准失效，保存并回读后再反馈成功；它不触发发送，也不把反馈自动升级为全局词库。进展由宿主自由表述，字数只是展示目标，不据此截断事实。

完成的批次保留简要结果，具体材料和过程仍能从岗位历史查到。演示页的浏览器存储不证明真实宿主持久化；缺少真实服务时禁用相应操作。完整行为与恢复语义见[同步接入说明](panel-sync-merge-2026-11-03.md)。

| 参考 | 用途 |

| [能力目录](../skills/job-hunting/references/capability-catalog.md) | 真正可执行的能力与停止边界 |

组件已提供宿主交互接口，默认 HTTP 服务仍只读。事件须绑定当前候选人、岗位和准确材料，由宿主调用既有业务服务，保存后重新查询。不得直接写 SQL、绕过门禁，或把普通点击当作批准。未知结果先核验，不自动重复外部动作。

实际验收须覆盖不同进展、渠道路由、排序、行点击、待办、完整历史、焦点和滚动恢复；再用合成数据验证一个已接通操作从点击、保存到重开后仍一致。失败、未知、冲突和未接入都有明确反馈。真实账号、模型和渠道分别验收，不为证明界面可用而试发招聘消息。
