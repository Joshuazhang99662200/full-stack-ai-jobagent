# Muse 源码通用模板还原记录

本轮由用户明确指定：以 [Muse 当前分享页](https://muse.ai/s/ui-xde6lxuxfxs74kd/nmGbS-bD-P6UW0oZ9dtEsPUMhNwg6mqdVPV6WwO5zb8) 为最终验收基准，复用 zip 的 React 交互源码。之前的 Console 清单实现保留兼容入口，不再充当 Muse 的默认页面。

## 两份来源及其差异

用户提供的 `codex-panel-package-2026-11-02.zip` 含 3427 行 React `App.tsx`、70 行 `theme.css`、API 声明及服务端动作源码。分享页实际为独立 HTML 示例，样式和若干弹窗内容与 zip 不同，不能把两份来源当成同一版本。来源摘要及变更例外记录在 `frontend/src/muse/provenance.json`。

| 范围 | 当前默认模板 | zip 复用点 |
|---|---|---|
| 导航与内容区 | 独立白色导航，1280px 容器 | React 状态与查询接口 |
| 主表 | 五列原比例、交替底色、渠道标签、红点 | 原排序及筛选函数；已结束沉底 |
| 顶部控件 | 匹配度/入库时间按钮、刷新、执行清单 | React Query 查询及失效刷新 |
| 待办 | 独立弹窗、依据、全文、选择及后果 | 决定保存后重新查询岗位，并核对决定编号 |
| 详情 | 匹配情况、进展、岗位要点、待核实、招呼稿/材料、工作记录 | 原岗位/材料查询、完整版本与 MaterialList |
| 执行清单 | 独立宽弹窗、岗位清单、确认执行、先不执行 | 已批准批次、准确材料绑定、逐项回读 |
| 运行与沟通 | 分享页的三列/四列表格 | 只消费已存快照，不补造执行者、消息或时间 |
| 数据说明 | 分享页计数口径与决定/执行文案 | 真实来源缺失另作明确提示 |

`MuseApp.tsx` 保留 zip 的全部 381 个字面量 className，`theme.css` 保留原字节摘要；`?template=zip` 可查看这份移植版。当前默认页面在 `MuseCurrentApp.tsx`，使用分享页全部 409 条原始样式声明，增加容器作用域及 Tailwind 重置后的列表圆点、标题字重恢复。两个入口均是 React 组件，没有把分享页的模拟脚本或数据库写入逻辑搬入前端。

## 通用化边界

- `MusePanel` 注入 `MuseActions`、附件预览目录及宿主配置。RPC 展示类型从 `src/jobagent/schemas/muse_panel.py` 生成，不另立岗位状态权威。
- `MuseSourcePanel` 将已有 `ConsoleDataSource` 转成相同接口。决定、修改意见、执行请求委托既有宿主服务；浏览器演示只接合成适配器。
- 分享页示例中的本地假发送、假回读、固定执行者与历史没有移植。zip 内个人轮次修补、自动播种、私有简历目录、个人次数与间隔也没有进入模板。刷新和执行间隔由宿主显式注入，缺省不自动轮询。
- 真实 HTTP 源仍为现有只读 GET。保存服务未接入时禁用决定和执行；待办源缺失显示未知。反馈仅能绑定现有待办中明确命名且材料版本一致的选项。屏蔽/重复判定、在线简历及其他缺失服务必须由真实宿主注入，不宣称已接通。
- 修改全文先保存新版并回读，再批准新版。批准不等于发送。执行仅确认当前准确批次；未知结果通过同一操作键核验，不自动重发。没有正向回读不能显示已执行。
- 简历、历版招呼语、实际发送全文与沟通原文从宿主已有记录读取。缺失来源明确说明；没有把私有材料打包到公开示例。

## 验证方式

来源指纹测试核对 zip 样式、381 个 className 和当前分享页的 409 条样式声明。浏览器测试覆盖默认 Muse 主表、详情、独立待办、保存后刷新、执行清单、运行/沟通/说明页、只读失败及 zip 对照入口。适配测试验证反馈保存、操作中断后的幂等核验、批准/执行分离与正向回读。

这些检查能验证已移植的结构、样式值与交互门禁，不能单凭测试通过声称任意宿主、任意数据下逐像素 100% 一致。实际招聘服务及缺失附件仍需宿主接入后验收。
