# 默认面板模板合并记录（2026-11-06）

本轮按用户要求，把真实面板代码包（Space「任务状态面板」2026-11-06 版 `client/src/App.tsx`）的页面框架合并为仓库默认的 Muse 前端，前提不变。合并结果在 `frontend/src/muse/MuseSpaceApp.tsx`。原默认模板保留为对照入口；代码包本身不进仓库，原因是其中含私有快照与简历。

## 入口

| 地址 | 模板 |
|---|---|
| `?demo=1` | 默认：合并后的 Space 框架（`MuseSpaceApp.tsx`） |
| `?demo=1&template=current` | 上一版默认：Muse 分享页还原（`MuseCurrentApp.tsx`） |
| `?demo=1&template=zip` | 最早的 zip 源码对照（`MuseApp.tsx`） |
| `?legacy=1` | 兼容 Console |

`MusePanel` 的 `appearance` 默认值改为 `"space"`，可选 `"current"`、`"zip"`。

## 不变的前提

- 批准与执行是两次点击。详情里的“批准并发送”先批准；保存成功并回读到决定之后，才出现“确认发送”。正文改过后，需要先保存草稿、回读一致，再重新批准。
- 一键投递只执行已批准的材料。原包中“勾选并点击即批准、不再复核”的文案和入口都已移除。
- 重新生成、保存草稿和决定都在回读核实后才显示成功；结果未知时提示先核实，不提供重试。
- 宿主没有接通的服务（选择队列、一键投递、重试、重新生成、决定保存）一律禁用并说明原因。读取失败时计数显示“?”，不会切换成演示数据。
- 个人节奏（发送间隔）、刷新与轮询周期、进展生成上限都只从宿主配置读取：`refreshMs`、`batchRefreshMs`、`progressBatchLimit`、`executionSummary`。前端不再自动发起进展生成。
- 删除原包里的个人迁移与对账动作（导入快照、修复匹配、对账队列、同步巡检等），也不再在前端用正则改写宿主文案。
- 写入后只刷新受影响的数据（`refresh.ts`）；只有宿主同步才全量刷新。

## 文案修订

逐条清单见本轮审阅交付。主要改动：

- 统一用词：招呼语、回读（面向用户写“已核实”）、批准、职位要求、未记录、改写记录、你的决定；去掉 signal、宿主、JD 等用户看不懂的说法。
- 列表表头“选”改为“选择”；“仅作参考”改为“仅供参考”；“已选 N 条”统一为“N 个岗位”。
- 修正病句和歧义，例如“在没有核实之前”“没有再重新决定”“那里也有再次执行”。
- 去掉内部编号和原始时间串；修正“。。”“。；”和多余的空格。
- 删除“先放一放”；“这版文案可以 / 帮我改一下”改为“文案没问题（先不批准）/ 招呼语要改”；已结束岗位的“继续了解”改为“重新打开这个岗位”。
- 写死的数据结论改为按实际记录显示：沟通原文有就列出，没有就写“沟通原文未保存，对方是否回复尚未核实”；数据说明页的计数补齐“其他状态”“尚未核对”。

## 验收

`tests/muse-space.spec.ts` 覆盖：默认入口与一键投递规则、批准不等于发送、改稿后必须重新批准、沟通记录缺失时保持未知、执行清单不显示内部编号、只读来源的未知计数与禁用写入、来源不可用时不回落演示，以及 390px 下无横向滚动。原默认模板的测试改为访问 `?template=current`，继续单独校验。
