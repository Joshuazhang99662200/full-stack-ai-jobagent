# 给 Muse：恢复原来的 Agent 面板设计语言

**本轮只修宿主界面的视觉与阅读方式。** 保留已经修订的五列、真实进展、审核与历史交互，不退回旧业务逻辑，也不恢复绿色版本。无需修改本仓库代码来完成这份宿主修订。

## 恢复到什么样

参照最早那张 AffectUI 风格的 Agents 面板：白色面板、浅灰边界、紧凑的逐行布局，状态只用少量浅蓝与小标记表达。它看起来是 Agent 正在汇报工作的工具，用户扫一眼就知道哪里在推进、哪里等自己处理。

这里恢复的是设计语言。早期图中的公共时间轴、分钟刻度、按 Agent 职责分行和模型名称不恢复；现在仍是一行一个岗位，保留五列内容和同岗并行工作。

目前截图的问题是：内容虽然已改，但页面回到了米色背景上的普通长表格；字号偏小，行间靠大量文字撑开，进展一栏变成长篇说明，待办入口难以辨认。只换白色背景不够，面板、文字、行、状态和操作需要一起恢复。

## 一、明确使用这套视觉基线

基线来自当前仓库 [styles.css](../frontend/src/styles.css)，可按宿主组件方式实现，不要求复制 React 运行环境。

| 元素 | 要求 |
|---|---|
| 页面与主面板 | 白色 `#ffffff`；外层可用很浅的冷灰。去掉米色纸张、暖黄表格及 Muse 默认主题带入的背景。 |
| 主要文字 | 深灰蓝 `#263143`，避免整页纯黑小字。 |
| 次要文字 | 灰蓝 `#647184`，公司、补充信息和次要状态与主标题拉开层级。 |
| 分隔与边框 | 很浅的灰 `#e7ebf1`，只保留必要边界；无粗网格、无每格描边。 |
| 蓝色强调 | `#286aa4`；浅蓝背景 `#edf4fc` 或 `#e4f0ff`。用于选中、焦点、正在推进及已完成流程节点。 |
| 等待提示 | 必要时少量浅橙 `#fff3dd`；不用整行橙色，也不将每个状态都做成色块。 |
| 本人待办 | 保留红点及具体动作文字；红点不代表未读、不装饰所有岗位。 |
| 字体 | 使用宿主可用的系统无衬线字体，中文可用 Microsoft YaHei / PingFang SC；正文通常约 14px，说明约 12–13px。不能靠缩小全页来塞更多内容。 |
| 圆角与阴影 | 约 6–10px 的克制圆角，主面板和弹窗可有轻微阴影；行内不层层套圆角卡片。 |

这些颜色是宿主样式参考，不显示在产品页面。不要恢复深绿主按钮、绿色大块、渐变、厚重投影或默认“报告文档”皮肤。

## 二、主视图仍是五列，但要像 Agent 工作面板

保留：**岗位｜渠道｜匹配情况｜进展｜待你处理**。

顶部只需要岗位进展标题、简洁状态计数与必要操作。计数参考早期面板里的“小圆点 + 简短状态”，不做一排大面积统计卡片，也不加一段介绍性副标题。

五列放在同一个白色面板中：

- **岗位**：岗位名称为主，公司在下一行；层级清楚，关键方向可换行，不把公司和岗位一起缩成细小文字。
- **渠道**：小而安静的文字标签或轻边框入口。它是来源和路由，不抢占进展的注意力。
- **匹配情况**：用简短结论和可选的已有评分，不把“基本要求符合、经历与要求比较接近”每行机械重复。详细依据进详情，不能用满分制造确定感。
- **进展**：占主要阅读宽度。保留 LLM 自由表达，但主表先呈现一两句重点，说明做到哪、等谁或卡在哪。较长背景收进“查看详情”，不要默认把全部说明铺在每一行。
- **待你处理**：红点加具体操作，例如“看看招呼语”“登录 BOSS”。真实无待办时保持安静，不能用空的主按钮占位。

按同一条横向基线对齐各列，上下适度留白，用浅灰细线分隔。常规行可从约 72–96px 的密度调起，但不设死高度裁掉岗位名或关键阻碍。鼠标移入仅轻微提亮，选中行用浅蓝或很轻的蓝色侧标记；不要把整行涂成饱和色。

岗位和进展获得主要宽度，渠道列窄一些。宽屏可以充分利用宿主可用宽度，不把整张表挤在窄小的纸张中央；窄屏保持同样信息层级，允许改为分组排列，不强行压成五列小字。

### 进展的视觉表达

早期面板的价值是“容易扫读”，不是给每个岗位画一条甘特图。现在可用短句、轻量状态和必要的小节点表达，不能恢复公共时钟或耗时色条。

例如实际有据时，主表可以写：

> 简历已发出，等 HR 回复。

或：

> 简历已发出。BOSS 需要重新登录，暂时查不到新回复。

完整的来龙去脉仍可在详情查看，但不在主表连续解释旧记录、匿名雇主、每次读取经过及所有不确定点。LLM 可以自由选择措辞，视觉层对长说明做渐进展开，不把自由表达变成不限长度的表格段落。

进展中最关键的事实不能被省略号截掉；若确需收起长文，应有清楚入口、可读全文，且不靠悬停才能看见。

## 三、详情弹窗也用同一种语言

条目布局与招呼语正文样式按最新的 [二级页修订说明](muse-detail-items-and-greeting-states-2026-11-01.md) 实施：关键字段独立展示；拟发送有文本框，实际发送灰色斜体且无框。视觉精简不再压缩成一段信息。

弹窗为白底、浅灰边框、适度圆角；遮罩不必过深。标题与关闭入口清楚，正文与主列表字体一致。弹窗内容随窗口留出边距，在弹窗内滚动，不用缩小整页。

保留已经确定的精简规则：

- 岗位信息和一句进展只出现一次，不重复分成多张卡片。
- 当前材料、具体问题和适用操作优先，其余历史按需展开。
- 不默认显示采集过程、技术字段、原始 JSON、空记录和大段机制解释。
- 删除不影响理解的副标题；通过间距和字重建立层级，不为每段加标题和边框。
- 完整旧稿、实际已发文本、简历文件与沟通原文仍可找到，不为了清爽丢内容。
- 底部 workflow 用紧凑节点或细线连接，完成蓝色、未开始或未记录灰色、当前标“现在”；不把每个节点画成大卡片，不附一大段图例。

从红点进入招呼语审核时，仍然先看 **JD 要点与关键词 → 招呼语全文 → 适用审核操作**。关键词可用少量浅灰或浅蓝轻标签；招呼语区域留足阅读空间，不被多个嵌套面板挤成窄条。普通详情底部不重新摆回全部审核按钮。

主要操作最多突出当前最重要的一项，用蓝色主按钮；其余为白底轻边框或文字操作。“放弃岗位”按最新要求直接外显为红色按钮，不藏在“更多”；删除“先放一放”，由右上角“关闭”按钮 关闭查看。按钮名字直接说明动作，避免每个按钮下面带一段小字。放弃仍按实际业务服务保存，不能仅隐藏卡片冒充完成。

## 四、Muse 应怎样实施这次恢复

1. **沿用已有数据和事件绑定。** 先保留五列、真实状态、材料与历史，再替换外层样式。视觉恢复不重新生成记录、不改写批准或发送事实。
2. **为这个面板使用明确的组件样式作用域。** 不再直接继承 Muse 默认表格、报告或富文本主题。检查背景、字体、边框、按钮和折叠区，而不只改一两个颜色。
3. **先恢复一屏主列表，再恢复一份详情与审核视图。** 用不同状态的合成数据检查，避免靠一条短数据掩盖长文和缺失情况。
4. **同一套样式应用到其余岗位。** 不能主表像 Agent 面板，点开却回到默认米色表单；新增组件继续复用这套视觉规则。
5. **实际打开宿主面板核对。** 页面能点击、材料能读、待办能处理；不能只交一张看起来像的静态图。

可参考仓库中的 [JobQueue.tsx](../frontend/src/JobQueue.tsx)、[JobDialog.tsx](../frontend/src/JobDialog.tsx)、[JobWorkflow.tsx](../frontend/src/JobWorkflow.tsx) 的面板、行、弹窗和状态处理方式。它们提供已有设计基础，不代表其旧文案、旧列数和只读能力是本次要回退到的目标。

## 五、恢复验收

- 第一眼是清爽的白色 Agent 工作面板，不是米色报告或默认长表格。
- 每行能迅速找到岗位、主要进展和本人待办，不需要读完一整段背景。
- 五列分工明确，字体正常，长岗位名和关键阻碍可读。
- 选中、推进、等待和本人待办清楚但克制，没有绿色版本和大面积色块。
- 主表、详情、招呼语审核使用同样的字体、间距、边界与按钮语言。
- 五列内容、LLM 自由表达、红点、精简审核及完整历史仍然保留；没有恢复时间轴或按 run_id 分行。
- Muse 提供修订后的实际主表、详情和审核视图，并列明未接通的操作。视觉恢复不等于业务接入完成。

本文件是本轮**视觉验收基线**。[五列与精简弹窗要求](muse-five-column-progress-2026-11-01.md) 继续决定内容和交互；两者同时满足。若宿主默认模板与本文件冲突，以本文件为准，不因重新生成页面而回落到默认皮肤。
