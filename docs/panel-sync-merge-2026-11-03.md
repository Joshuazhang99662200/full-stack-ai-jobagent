# 2026-11-02 面板增量合并核对

用户提供 `codex-sync-2026-11-02.zip` 与 `panel-sync-2026-11-02.md`。实际为五项增量，另有未包含在 23:29 代码快照中的进展列补充。附件作为待核对来源，不执行其中的投递脚本、数据库迁移或私有路径回填说明。

## 差异与合并顺序

1. 复用 `ChannelTag` 与唯一品牌色表，覆盖当前模板的列表、详情、待办、执行与渠道提示。
2. 增加常驻选择栏、行选择、全选、反选、取消及清空，通过宿主接口持久保存。合成演示存储明确隔离；真实来源未接入时禁用，不用浏览器存储冒充服务端。
3. 快捷执行保留旧清单入口。用户在本次会话确认：只执行当前准确正文和附件已获批准的岗位；未批准项说明原因并留在队列，不在动作内自动批准。请求不阻塞其他岗位操作，启动与完成均按回读核验。
4. 拟发送稿提供重新生成和保存修改，追加保留改前/改后全文。生成由宿主 AI 服务提供，不用字符串改写冒充 AI。仅查看或无变化不记录；猎聘不提供招呼语；signal 不改词库。
5. 从已有逐项回读展示失败原因、时间和岗位/渠道累计次数；失败待办提供用户主动重试，未知结果保留未知且不重试。失败只是执行展示状态，不改 canonical 九态或擅自关闭岗位。

## 不能直接照搬的差异

- `executeSelectionDirect` / `executeJobDirect` 会在动作中批准未审阅材料；本次按用户确认改为仅消费已有准确批准。
- 新版 `TodoDialog` / `JobDetailDialog` 先显示保存成功，再后台核验，且核验异常被忽略；继续使用现有先回读再确认成功的顺序。
- `recordExecResult` 仅用 `done`、`failed` 和任意字符串表示回读，不足以替代仓库的材料版本、正向证据与观察时间校验。保留成功、失败、未知，缺证据不显示成功。
- MD 对失败项是否移出队列自相矛盾；代码只在成功分支删除，合并采用成功移出、失败及排除项保留。
- 末尾补充不在 zip 代码中：结束后仅显示批次汇总，逐条原因归各岗进展和历史；执行中可逐条跟踪，旧执行前清单保留排除原因。
- 不补造历史失败或时间，不把所有失败自动升级为本人待办；只对确需本人决定是否再次执行的明确失败显示重试入口。

测试采用合成数据与注入的宿主端口，不触发真实发送、投递或登录。源码差异保存在本地忽略目录；公开提交仅包含通用组件、契约、合并说明和合成测试。


## 接入状态与实现位置

- 默认当前模板：`ChannelTag.tsx` 是唯一品牌色定义；`SyncControls.tsx` 提供选择栏、复选、重新生成、改写历史、底部执行流程及批次进度；`MuseCurrentApp.tsx` 组合这些组件。
- `schemas/muse_panel.py` 依据包内请求/响应声明扩展到 91 个展示模型，生成客户端 RPC 类型。没有执行服务器源码或导入上游数据库模型。
- `syncAdapter.ts` 是明确的合成参考实现：选择与排除记录按候选人隔离保存；快捷执行调用既有审批和批次服务；未知请求只核验；`executionFacts.ts` 从已保存且已选择的逐项回读计算失败档案，不补造时间或历史。
- 真实宿主通过 `MusePanel.actions` 提供完整接口，或通过 `MuseSourcePanel.syncActions` 注入相同选择/执行/生成接口。选择须持久写入服务端；新稿及改前/改后记录须由宿主在同一业务事务内追加保存。真实 HTTP 源仍只读，缺失接口禁用并解释。
- AI 重新生成默认未接入；没有用固定句式冒充 AI。注入式测试模拟宿主提供新稿与 signal，验证回读后才显示成功、编辑锁定、旧批准失效、无批准无发送。
- `?template=zip` 保留最初源码对照，`?legacy=1` 保留兼容组件；本次增量应用于默认通用模板，不把旧对照入口误称为新版宿主。
- 直接引用包内脚本优先或浏览器兜底流程不产生执行授权。本轮没有复制或运行 `liepin.py`，也没有执行任何迁移或真实渠道动作。
