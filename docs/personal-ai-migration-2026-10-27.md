# Personal AI 宿主迁移

日期：2026-10-27。用户已选择以最小代码量迁移到 Muse 等个人 AI，公开仓库分发，各人在自己的会话提供履历与 Markdown。本轮不连接真实 Muse 账号、不创建定时任务、不发送招呼或投递。

## 方案与边界

采用“宿主操作 + 便携规则 + 现有业务门禁”：GitHub 提供版本化入口；Muse 自己负责网页、文件、推理、定时与通知；现有 Python 核心在具备执行能力的宿主私有工作区运行。本机 Codex、浏览器驱动、CLI 中继、飞书、隧道、Webhook 和后台服务均不是新入口的依赖。

仅靠提示词的方案代码最少，但不能提供确定性校验；新增远端服务可统一强制执行，却增加部署、认证和多租户存储。本轮选择复用核心，仅增加一个无副作用的搜索学习入口。缺少 Python 的宿主只读取协议、整理资料与草稿，不能声称已完成程序门禁或获准自动发送。

历史本地适配器保留为兼容模块，不从 Personal AI 路径调用。直接删除会破坏既有使用者，也无助于解除新入口对本机的依赖。原工作区已有未提交更改；本次从 GitHub main 的干净快照实现，单独发布，随后将本轮增量同步回原工作区。

## 两层记忆

第一层保存原始 signal：本人主动添加的正例岗位、明确喜欢/不喜欢、文案修改、真实招聘方回复与观察不到回复。每条包含候选人、事件编号、来源、完整 JD 快照、时间、本人原话和可逐字回查的特征引文。单纯粘贴一个待分析链接不自动视为正例。

第二层保存可撤销的搜索偏好假设：从本人正例归纳特征，再回查第一层独立岗位、公司和明确反例。至少两个不同岗位、不同公司支持且没有明确特征反例，才把特征词加入软优先级。一个反例使该假设 contested。拒绝整个岗位而未说明特征原因，只影响该岗位；没有回复不等于不喜欢岗位。文案反馈和招聘方回复保留为原始信号，不直接变成搜索偏好。

每轮从完整原始台账重算，自动反映新增或撤回的偏好；重复事件幂等，同号异文拒绝。保留基础查询，只新增最多两个有依据的查询，不改变硬条件、候选人事实、匹配分数或发送权限。这是可审计的保守启发式，不宣称统计显著、因果效果或模型训练。

## 通用入口与验收

`hosts/personal-ai/README.md` 提供 GitHub 加载、能力检查、个人资料初始化与运行路径。`memory.md` 说明双层记忆及 JSON 输入；`tasks.md` 给出搜索轮询和逐项审批后发送的任务文本。模板无真实候选人、联系信息、Cookie 或本机路径。

GitHub 能读文件不代表宿主能运行 Python、保存私有文件、续跑任务或登录招聘网站。必须分别取得读取版本、私有状态写入后重读、两站各一条完整 JD、停止/恢复与发送回读的证据。用户尚未开始设置 Muse，真实接入状态保持未验收；交付可复制启动文本，不冒充已经安装。
