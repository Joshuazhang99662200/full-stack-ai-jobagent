# 轮询控制台

控制台提供可复用的 React 组件、本地只读页面，以及供宿主使用的同一份 JSON 查询。主视图按岗位组织，每行像 Agent 汇报这个岗位的进展：做到了哪里、正在做什么、接下来准备做什么、需要本人处理什么；轮次与 run_id 保留为追溯信息。它展示已有事实和明确上报的执行活动，不负责调度、生成、审批或发送。

## 岗位汇报与并行工作

首列为岗位和公司。活动只根据明确的 job_id 与该候选人的岗位或可靠的 normalized_job_id 关联，不能把整轮活动猜成属于某个岗位。同一岗位跨运行的同时工作分别列出；不把 fetch、起草、复核等画成全局串行步骤，也不画分钟刻度。

“接下来”只来自宿主登记的 `next_step`；未登记时显示“下一步尚未安排”。“需要你”只来自明确的 waiting 事件（结合运行的等待类型写清要做什么）、待核对的硬筛、暂停、待面试和多条未结束联系记录。顶部计数仅是筛选，不改变寻源预算或任务调度。未归属岗位的活动保留在快照及运行追溯中，不能补造关联。

排序先按“需要你、正在推进、等待对方、暂无进行中、已关闭”分组，组内参考同一候选人最近已存的硬筛结果与匹配结果；通过硬筛、匹配较高的岗位优先。缺少评估明确显示未评估，不视为零分。旧评估保留时间、策略和输入摘要，仅供展示，不代表按当前配置重新评估。

执行失败、取消运行、暂停或心跳过期不会自动关闭岗位。沉底只改变显示位置，不改写九态，不触发放弃、重开或发送。

## 三个维度

主列表显示岗位渠道，点击岗位、渠道或待处理事项打开详情弹窗。默认通道为 Boss、智联的内容布局；猎聘采用独立展示路由，隐藏招呼步骤及相关业务页面，完整源字段仍可在原始记录中核查。此路由只控制展示，不增加当前后端的猎聘 pipeline 能力，不自动加载未接入的私有 SQL 表或执行外部操作。

弹窗按进展、材料、历史、Signal/Harness、原始记录组织；仅展示查询返回的字段。没有关联运行或信号时说明未接入，不将空值写成成功，也不提供无后端消费者的操作按钮。

详情弹窗底部在所有页签保留工作流程。完成节点显示蓝色，未开始或未记录节点显示灰色；当前执行或等待节点标“现在”，同岗并行工作可同时标记。缺少记录不推断已完成或尚未开始；心跳过期、失败和关闭分别保留真实提示，关闭后不标当前节点。节点来自现有宿主观察，不新增九态，也不证明本人批准或实际投递；猎聘流程不显示招呼步骤。

| 维度 | 来源 | 用途 |
|---|---|---|
| 运行状态 | HarnessRun.phase | 区分运行、等待本人、登录受阻、结果未知、结束 |
| 当前活动 | 宿主显式记录的活动事件 | 显示 fetch、详情、匹配、起草、复核、审批等待、回读、汇总 |
| 岗位九态 | PipelineJob 与 PipelineHistory | 显示岗位业务状态及有证据的转移 |

待审批不增加岗位业务状态。岗位可能在索取简历时等待某份材料审批。九态按实际历史高亮，不能按枚举顺序推断经过所有阶段。

## 宿主读取完整字段

从仓库根目录执行：

```powershell
jobagent console definitions
jobagent console list CAND_DEMO --database .jobagent/jobagent.sqlite3 --workspace .
```

`CAND_DEMO` 是合成标识，使用时替换为当前已确认的候选人 ID。definitions 提供 JSON Schema，包括原有岗位、元数据、历史和运行契约。list 返回这些完整业务字段，包括 JD、准确招呼语、版本、摘要、证据引用和产物引用；前端没有显示的字段也能从详情展开。凭证配置不属于此接口。

数据源状态必须和结果一起读取：complete 表示该来源已读取；missing、invalid、unsupported 表示缺失、无效或尚未接入。数组为空不能独立证明该来源成功或已遍历全部站点。读取不创建数据库、不迁移、不确认 worker 事件，也不取得运行租约。

## 本地页面与组件

首次准备需要 Python 项目环境及符合 frontend/package.json 要求的 Node.js。前端依赖锁定在 package-lock.json；构建后运行不需要 CDN 或外部字体。

```powershell
cd frontend
npm.cmd ci
npm.cmd run build
cd ..
jobagent console serve CAND_DEMO --database .jobagent/jobagent.sqlite3 --workspace . --assets frontend/dist --port 8765
```

浏览器访问 `http://127.0.0.1:8765`。真实视图读取同源 `/api/snapshot` 和 `/api/definitions`。页面及接口只读；服务只监听本机，拒绝跨来源请求和不匹配的 Host，不提供任意本地文件下载。

演示入口显式使用 `?demo=1`，并标注合成数据。真实请求失败时不会自动换成演示或显示成功零结果。不要把真实快照放入前端 public、构建目录或仓库。

独立页面通过“刷新记录”读取最新本地快照；当前没有后台自动刷新。嵌入组件的宿主可以自行管理快照更新频率，这不会改变实际巡检任务的调度频率或查询额度。修改 Python 契约后，运行 `python scripts/build_console_demo.py` 重新生成公开示例与 JSON Schema，再重建前端。

React 组件的导出和嵌入示例见 [frontend/README.md](../frontend/README.md)。宿主可调用相同 JSON 查询，再把快照作为组件输入；无需依赖本地 HTTP 服务。CLI 和本仓库 MCP 桥接的只读出口共用查询实现，宿主选择适合自身的接入方式。

MCP 桥接启动时可显式指定工作区，避免自定义数据库路径导致运行目录识别错误：

```powershell
python -m jobagent.bridge.mcp_server --database .jobagent/jobagent.sqlite3 --workspace .
```

对应只读工具是 `console_list`（传 candidate_id）和 `console_definitions`。修改桥接版本后，需要宿主重新加载工具目录；已连接的旧进程不会自动得到新工具。

## Muse 交互式面板

在 Muse 中，Agent 应按固定的仓库版本，在宿主提供的组件或应用环境中自行构建交互式岗位面板。可复用 React，也可用宿主支持的组件实现同等交互；交付须包含真实事件处理与业务结果更新。静态截图、只读 HTML 和仅可展开的快照只能作为预览，不能作为业务交互已接通的验收结果。

本仓库的 `Console` / `SourceConsole` 已提供可注入的宿主交互接口；`console serve` 和查询工具仍只读。宿主需要实现业务服务适配，明确声明已接通的操作，不能把合成演示当成真实审批、放弃或投递。也不应依赖维护者电脑上的 localhost 服务。接口见 [宿主交互说明](react-console-host-interface.md)，此节尚未代表真实账号已联调。

### 交互与业务接线

| 用户操作 | 面板应提供的响应 | 能力不足时 |
|---|---|---|
| 筛选、选岗、点击渠道、打开详情 | 立即更新视图和对应岗位内容；保留原始记录及 workflow | 标明缺失来源，保留诊断 |
| 点击“需要你” | 打开具体事项、准确材料和处理入口；告知需要本人决定什么 | 显示具体阻塞原因和人工处理方式 |
| 准备或修改材料 | 调用既有起草/复核能力，保存新版本并显示全文、附件与差异 | 标明草稿或未复核，不冒充已批准 |
| 本人决定放弃、拒绝或继续 | 展示操作含义和目标岗位，由真实用户事件触发对应业务服务，保存决定后重新查询 | 禁用操作并说明缺少服务；不能只让卡片沉底冒充已放弃 |
| 审阅并批准某份材料 | 展示具体岗位、准确全文、实际附件及版本；将本人明确决定交给既有审批流程校验 | 按既有对话审批方式交人；普通按钮点击不自动成为有效审批记录 |
| 执行已获批投递 | 单独核对批准绑定、渠道能力和发送前门禁，实际执行并正向回读后刷新结果 | 禁用执行入口并说明；结果未知先核验，不自动重复发送 |

事件处理顺序为：用户操作 → 绑定当前候选人、岗位及当前材料版本 → 宿主调用已落地的业务能力 → 检查业务结果并保存回执 → 重新查询事实源 → 更新面板。等待、失败、版本冲突和结果未知都应有明确反馈；禁止乐观显示“已批准”或“已投递”，禁止用界面局部状态或直接改 SQL 代替业务服务。可用能力以 [能力目录](../skills/job-hunting/references/capability-catalog.md) 为准，未落地的能力不临时在面板中另造审批或发送逻辑。

### 最小验收

在 Muse 的实际运行环境中验证选岗、渠道切换、弹窗、工作流程与“需要你”跳转；用合成数据验证一个受支持的业务操作从点击到持久化、重新查询及重新打开后仍一致，同时验证失败和未知结果不会变成成功。未接通的动作须能看到禁用原因。真实招聘发送的验收仍须另有本人对具体正文和附件的批准，不能为证明面板可用而试发消息。验收时分别列出已验证交互、已验证业务写入及未接入能力，不能笼统写“面板已打通”。

## 记录阶段

阶段记录是宿主对正在执行活动的观察，不能提升为审批、发送、已读等业务事实。记录须绑定已存在且属于该候选人的 HarnessRun；涉及单个岗位时必须登记准确 job_id，跨岗位的采集活动可以不绑定并保留在未归属清单。运行已结束后不能继续宣称正在执行。

宿主在实际开始阶段时记录 started；仍在执行时记录 heartbeat；等待本人或外部条件时记录 waiting；真正结束后记录 completed 或 failed。每个事件具有独立 event_id，同一阶段沿用 activity_id。失败和等待保留恢复点、产物及证据引用；重放同一事件必须保持原内容。

把输入 JSON 保存到私有目录，再运行 `jobagent console event <私有输入文件> --workspace .`。下面是合成字段示例，run_id、候选人、编号及时间必须替换为当前真实观察；不得把示例当作过去已经发生的事实导入：

```json
{
  "event_id": "EVENT_DEMO_FETCH_START",
  "candidate_id": "CAND_DEMO",
  "run_id": "RUN_AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
  "activity_id": "ACTIVITY_DEMO_FETCH",
  "activity": "fetch",
  "status": "started",
  "occurred_at": "2026-10-31T09:50:00+08:00",
  "owner": "synthetic-host",
  "checkpoint_reference": "PRIVATE_CHECKPOINT_DEMO"
}
```

同一 activity_id 的 owner、job_id 和 activity 不得更换；阶段结束后须使用新活动编号。可选的 `next_step` 由宿主写明自己接下来准备做什么，界面原样显示最近一条；它只是计划说明，不授予发送或审批权限。recorded_at 由程序登记，宿主不能在输入中冒充登记时间。默认超过五分钟没有活动观察时，运行新鲜度显示 stale；这是界面可观测性的提示，不影响业务超时、查询额度、放弃策略或原任务调度。

开始时间缺失就显示“未记录”，不从完成事件倒推耗时。心跳过期显示“状态未确认”，等待本人不显示为持续计算。过去没有记录的运行可以显示已有状态，不能补造曾经检查、审批或发送的事实。

## 现有数据的范围

原有 pipeline 已提供完整岗位字段和九态历史，平台契约目前为 Boss、智联。Harness 已有运行状态和产物；旧 worker 事件主要是完成记录，不能还原每一步的开始时间。新阶段记录需要宿主按协议实际调用，单纯启动页面不会替宿主记录。

原有全局轮询与外联审批记录并非都绑定候选人和运行；没有可靠关联的来源会报告尚未接入，不能混入其他候选人的数据。审批仍通过既有逐项、绑定准确文本及附件的流程完成，控制台不授予操作权限。
