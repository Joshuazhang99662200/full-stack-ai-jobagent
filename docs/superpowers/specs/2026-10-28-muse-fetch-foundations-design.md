# Muse 寻源策略基础修订

基准：38afd89ec1ed41ca048fcb23f1c98279f6f9f180。用户已确认岗位偏好与文案反馈拆分，并要求同步修正薪资规则与预算。本次独立于旧桥接裁剪实验，不提交、不推送。

## 本次交付

1. 搜索学习沿用 SearchSignal / learn_search，增加 feedback 事件。job_preference（like/dislike/neutral）与 message_feedback（accept/revise/reject）分别可选，至少有一项；均须本人原话。仅显式岗位偏好影响搜索假设，文案修改不擦除先前岗位偏好。旧 like/dislike/user_added 仍可重放；同岗位最新显式选择生效，neutral 撤销先前正负信号。拒绝特征仍须本人原话点名且有 JD 引文。
2. CandidateFilterContext 默认 compensation_comparison=upper_bound，区间达到本人底线即通过，明确上限低于底线才拒绝。只知达标下限也可通过，无法确认或币种/周期不可比保持 REVIEW，不猜测换算。lower_bound 仅为本人显式选择的更严格模式。既有 unstated_compensation_passes 为显式面议例外，不适用于明确区间上限低于底线的薪资。
3. 新增按站点的寻源轮次、尝试与结果账本。查询与详情分开预占；列表观察数在查询结果记录。默认每轮每站 3 个查询、20 次详情尝试，查询上限 6；来源每日详情硬上限继续最多 50。用户可降低轮次额度，不能超过来源硬上限。重复/失败/取消均不退还预占。相同行动 ID 重放幂等，异文拒绝；BEGIN IMMEDIATE 保证并发预占不超额。
4. 轮次额度在创建时固定；旧轮次跨来源当地日不能继续，需开新轮次。每日额度按 Asia/Shanghai（当前 BOSS/智联协议）计算，跨候选人但同一私有数据库共享站点消耗。详情尝试必须注明站内岗位 ID 和 URL，查询注明准确查询词。
5. gate 结果追加后，该站当天停止新预占。未知网络结果不得通过换行动 ID 自动重试规避；宿主保留检查点交人。预占只能约束遵循协议的宿主，不能证明 Muse 真实执行或身份已接通。
6. sourcing-budget 保留旧输出字段，改为实际尝试 + 未被当天尝试覆盖的已保存岗位估算；明确 legacy_unmetered，旧记录不能补造精确读取历史。重复读同岗仍逐次计入。
7. 修订宿主协议：先预算、预占、列表、去重/预筛再详情；少结果可有限移除软限定，跑偏可增加有据限定，重复多可换组合，摘要不得当全文。保持稳定查询、探索与冷却回访，不自动放松硬条件。每轮保存报告，零结果也有私有记录；通知仍按用户设置，避免把“有报告”理解为每轮必须打扰。

## 边界

审批、发送租约、候选人事实确认、审计调用点均不改动。模型、浏览器、定时与私有文件仍由 Muse 提供。本次不声称实现 JD 版本库、Markdown 词库解析、LLM 因子化、查询组合引擎或真实 Muse 接入；这些需要下一阶段独立契约与验收。

公开仓库仅放代码、文档及合成测试；真实薪资底线来自本人私有配置，代码不写死 18k。

## 验收

- 明确喜欢岗位同时修改招呼可作正例；仅接受/修改招呼不增加或撤销岗位信号；neutral 可撤销。
- 15–25k、15–18k 对18k底线默认通过，15–17k拒绝；lower_bound 仅显式启用；未知/不可比 REVIEW。
- 同岗重复两次读取计两次，失败占额，重复行动 ID 不二次消耗；并发末位预占仅一个通过；午夜按站点日切换。
- 旧数据库从 v13 迁移，原表和批准数据保留；完整 pytest、Ruff、mypy、git diff --check 通过。
