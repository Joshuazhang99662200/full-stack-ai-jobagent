# 统一记忆原型：已验证能力与公开结论

当前可定位为经过受控实测的记忆系统原型：反馈可以经已有学习服务归纳、版本化保存，再由来源、快照和上下文入口读取。来源身份、重复事件和部分非法输出有代码约束。持续学习收益、范围语义和文字事实一致性仍待验证。

调用方式见 [第一期说明](unified-memory-p1-2026-11-02.md)，长期目标见 [完整方案](unified-memory-muse-plan-2026-11-01.md)。本页是脱敏的实验摘要，不包含真实候选人、模型会话或私有数据。

## 代码能做什么

- `memory status` 盘点显式私有来源，区分缺失、空、不可读、无效与未接入；不迁移业务库。
- `memory compile` 在独立私有库保存来源元数据快照；同源幂等，不复制业务正文或调用模型。
- `memory context` 按候选人、任务和已支持范围读取，并重验来源摘要；来源变更或冲突时保留诊断。
- `PreferenceLearner` 为成功消费的完整反馈保存摘要。同号同内容可重放，同号异内容在模型调用前拒绝；历史缺摘要时不补造认证。
- 新建或改写规则须引用本次新增的来源事件；混入无关新事件不能使只引用历史来源的改写通过。完整不变的旧规则及真正有新来源的改写继续可用。

新增接口没有接管候选人事实、正式审批或发送，也没有把模型输出升级为本人确认。

## 受控实测怎样进行

2026-11-02 启动、2026-11-03 复核。按用户指定，Astra 生成案例并独立评阅，本地 Antigravity CLI 调用 Gemini。所有模拟意见明确标为合成，不作为本人的真实偏好。

共生成 16 个案例，开发与封存各 8 个。每组有 6 个记忆案例、2 个文字案例；开发组文字案例仅作参考。开发阶段结束后固定代码、题目与标准，再打开封存集。封存失败后没有修改本轮代码或答案来改变结果。

| 检查 | 结果 | 能说明什么 |
|---|---|---|
| 开发组固定提案 | 修复前 5/6，修复后 6/6 | 修复了历史来源单独支持新改写的缺口 |
| 封存组固定提案 | 5/6；一例错误放行 | 范围语义仍存在缺口 |
| Gemini 自然生成记忆 | 4 次：独立评阅接收 3 次，Schema 拒绝 1 次 | 模型可运行，结构守卫可拒绝非法提案；不等于 4 次成功学习 |
| Gemini 自由文字 | 2 次，语义通过 0 次 | 缺记录仍可能被误写为否定事实 |
| 模型前处理 | 来源冲突拒绝 1 次，纯重放复用 1 次 | 这两例未调用模型，不计入模型成功率 |

封存组共 8 个案例、6 次新 CLI 会话，均请求 `gemini-3.8-flash-low`。固定故障提案与模型自然生成分开评价：模型生成另一份合法提案时，不套用故障提案的拒绝答案。

记忆生成实际调用 `PreferenceLearner`，只提供当前记忆、新反馈、输出契约和通用协议，不提供预期答案或评语。接收结果保存后由新进程读取；拒绝与重放不改文件。两道文字题直接调用 Gemini，没有经过生产招呼生成器。

输入隔离采用独立会话、白名单、禁用工具和文件摘要核对。没有验证操作系统账号或容器隔离，也未单独审计完整内部 HTTP 载荷及服务端模型身份。

## 保留的失败与限制

1. 新来源编号有效，不证明它支持规则的含义。一例把单岗意见扩大为所有岗位的固定提案仍被代码放行；自然生成本次做对不弥补代码缺口。
2. 一例模型生成相互矛盾的范围字段，Schema 拒绝且文件未改；这是拦截成功，学习任务仍未完成。三例接收提案中还有一例长期适用意图不充分，不能视为真实本人长期确认。
3. “草稿阶段”不能推出未审批或未投递，“没有发送回读”不能推出未发送。两个文字案例仍犯了这些错误，并出现多余技术措辞。
4. 样本小、每例只生成一次，职业标签不证明跨职业泛化。没有证明搜索或写作持续变准，也没有验证回复率、面试率或因果改善。
5. 统一使用回执、结果关联、运营分析接口及 Muse 真实接线尚未完成。`usage_verified=false`、`learning_updated=false` 继续准确反映生产接入状态；实验回执不改变它们。
