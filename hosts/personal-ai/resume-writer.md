# 简历专用角色的宿主调用

简历任务使用 [唯一简历路由入口](../../skills/job-hunting/optimizer/SKILL.md)。实际可派发的角色任务、输入、输出和恢复边界见 [Writer workflow](../../skills/job-hunting/references/optimizer/writer-workflow.md)，这些参考随独立技能包分发。

宿主先核对本次改写方式；未选择时展示入口的三选一并等待。本次已选就沿用。准备完整原件/模板的结构去向清单，再取得既有 `optimizer tailor` 请求，将角色任务和请求交给宿主真实的 Agent 工具。调用后记录工具返回的实际任务引用和输出，读取结果，再按请求的 `resume_argv` 进入现有独立 review 与 assemble。

不要求厂商凭证，不写全局 Agent 配置。没有真实调度接口时说明专用 Writer 调度未接入，可由宿主直接继续已授权写作并如实标注；事实复核仍须独立上下文，缺少时停在内部草稿。角色 Markdown、`agents/openai.yaml`、交接文件或前端状态都不证明 Agent 已运行。

草稿疑点是内部工作步骤，留在既有私有工作区；不新增数据库状态机、草稿 CLI 或 schema。待补证条目暂存，其余内容继续优化，最终提交时满足当前证据与完整正文契约。模板及 PDF 按本次选定模式验收；不让默认一页 renderer 覆盖原结构或选定模板。

宿主报告区分内部稿、事实复核、完整文档制作、逐页验收与本人逐份批准；只记录实际完成的环节。按既有任务协议记录真实开始、等待与恢复点，不能用写作完成推导已批准或已发送。本说明仅提供调用路径，不宣称运行中的 Muse 或其他宿主已改写或完成真实接线验收。
