# 宿主定时任务协议

动态参数启用后，每轮先读取私有 `rules effective` 并核对当前候选人与版本。使用支持的入口时显式传入当前 `--rules-file`，缺值、过期或冲突就暂停相关步骤，不换仓库默认。将 `pending_changes` 的变量名、旧值、新值、生效版本附在改后首轮报告中；只有真实通知成功并回读后才登记 acknowledge。暂停窗口以变量求值结果为准，安静退出，不搜索、起草、推送或读消息；变量求值不等于创建/修改宿主定时任务。详见 `skills/job-hunting/references/dynamic-variables.md`。

定时由 Muse 等宿主提供。公开仓库不创建本机计划任务、守护进程、隧道或推送桥。初始化能力验收通过后，向本人一次性收集时区、频率、运行时段、每轮上限和通知方式，再保存真实任务 ID 和下一次运行时间。没有设置就不默认全天轮询。

## 搜索与起草任务文本

> 读取我私有工作区中固定仓库版本、候选人 ID、已确认证据、硬条件、基础搜索词、双层记忆与上轮检查点。不要读取其他用户的资料。若已有本轮运行则退出并记录重复唤醒，不并发操作同一站点；宿主必须提供持久任务锁，无法验证就采用人工单轮模式。先处理新增的本人 signal，调用 learn-search 重算 L2 并回读保存结果，保留基础搜索中的探索名额。只用你自己的已授权网页能力，在 BOSS 和智联逐站搜索，遵循本人频率、每轮限额和来源预算。读取完整 JD，记录来源 ID、链接、时间、查询词与完整性状态，查重再导入；只有列表时保留为未完成，不生成定向合格稿。先硬筛选，再结合已确认证据匹配，解释强项与缺口。对合格岗位直接生成完整招呼，并单独复核每项事实和表达。展示来源、岗位、完整草稿与待确认事项。新消息与用户主动加岗写入 L1；调用学习命令不代表有人批准。只在有新的合格岗位、真实新消息、失败或需本人操作时通知，无变化保持安静。任何登录、验证码、风控、限流或未知结果立即暂停相应站点并通知本人，不自动重试。最后保存查询、已看岗位、策略版本、完成步骤及下一步，重读确认后结束。

本任务不发送招聘消息、不投简历、不修改在线资料。未完成的审批在下轮继续展示状态，不能因为超时或定时唤醒而变为批准。

任务开始时回显候选人、目标岗位、策略版本、来源清单和实际预算；配置不符就停，不带入其他人的 PM 或技术岗位偏好。每次读取详情或完整面板前，用 `jobagent jobs reserve-read` 预留额度，随后用 `jobagent jobs record-read` 记录真实结果。输入字段以同版本帮助与契约为准；失败、重复读取和未入库也计数。保存每条输入的去向，再用 `jobagent jobs check-coverage` 校验覆盖报告；预算停止或登录失效都属于部分完成，不能写成无新岗位。

岗位正文的旧观察追加保留，不用新正文覆盖“当时未保存全文”的历史。平台岗位 ID 与内容版本分开，发送/拒绝/关闭状态不能被重新发现重置。单窗口等界面偏好只影响所属宿主任务，不自动关闭用户或其他任务的窗口。

## 获批动作：单独触发

> 只有读取到本人对具体岗位、准确全文和实际附件的有效审批后，才处理这一项动作。用同版本 JobAgent 核心重新校验审批摘要、目标、内容、附件、站点租约、查重与发送节奏；许可不满足就停止。宿主执行前重新确认页面岗位和招聘方，准确使用获批内容。一次只处理一项，回读实际结果并保存审计。发送结果不明时记 unknown/intervention，先核对平台，不能重发；新正文或新附件重新审批。没有程序门禁、独立复核或准确回读能力时，把已准备材料交给本人操作，不把提示词判断称为程序放行。

这是逐项执行协议，不是批量无人值守投递。首次接入先用合成数据演练许可失效、重复触发和失败恢复。真实发送需要本人的实际逐项批准，不能为了“验收接入”先发一条。

## 首次接入验收记录

在用户私有区逐条保存下列证据与结果；尚未执行的标为 `unverified`：

1. GitHub：实际读取到的 commit SHA 与三个入口文件。
2. 私有记忆：随机标记写入与重读；新会话能恢复同一候选人且不混入他人资料。
3. 学习：合成单正例不激活，两个不同公司正例激活，明确反例使规则 contested，重跑版本不变。
4. 网页：BOSS、智联分别一条完整 JD，来源与原文能回查；只证明各自读取能力。
5. 定时：真实任务 ID、时区、下次运行、单实例保障与暂停/恢复试验。
6. 审批：合成演练中正文或附件变化后旧审批失效；不实际触达招聘方。
7. 发送：留待本人批准具体一项后核验。六项通过也不提前宣称第七项通过。

任一能力失败，报告具体缺项和当前可用范围，不搭建新的本地控制链来弥补。
