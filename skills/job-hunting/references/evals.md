# 评测埋点与在线简历边界

当前是 P0 部分埋点阶段。调用前先核对 [能力目录](capability-catalog.md)；源码仓库中的完整设计为 `docs/evals-design.md`。设计已定不代表全部命令已实现。

## 已落地的记录

- 平台清单的 `observability` 声明 `read_markers`、`delivered_markers` 和 `profile_views`。空的已读标记列表表示无法观测已读；`profile_views: null` 表示尚未实测。缺失不能当成零。
- `patrol snapshot` 保留整份消息列表，并按声明提取我方最后一条消息的已读/送达回执。可选的 `our_status` 只能来自列表明确展示的状态，看不到就用 `unknown`。对方文本里的状态词不作为我方回执。
- 对话按平台、规范化公司名匹配；同公司有多条时用职位名区分。返回 `unmatched` 的行交人核对，不猜最近的一条。
- 回执按对话和状态只追加首次记录，不代表消息的实际送达或已读时间。`patrol receipts` 按时间顺序重放所有已存快照，补充尚未记录的回执；重复运行不重复插入，已有记录不改写。
- 导入观测的 `search_term` 保留实际检索词原文，独立追加到 `job_search_hits`；未采集的历史不从职位名猜补。
- 招呼草稿保留 `variant`、`hook_requirement`、`experiment_id` 等标签，标签只作记录，不分配实验或改变审批。起草招呼与回复时记录规则文件摘要对应的 `HarnessVersion`；重复内容保留首次版本记录。回复重写可保留首稿摘要及审批事件中的改写标记。
- `profile snapshot <字段文件> --platform <站>` 保存宿主只读抓取的 `{name, text}` 字段列表。首次生成 baseline 版本，内容摘要变化时生成 external 版本；同样内容只存快照，不重复开版本。`profile versions --platform <站>` 查询版本及变化字段，结果不回显简历正文。输入文件与数据库只放私有目录。

回填会写本地数据库。先确认使用的 runtime 支持当前 schema，并备份库，再在明确的目标库上运行：

```powershell
jobagent patrol receipts --database .jobagent/jobagent.sqlite3
```

这是本地记录操作，不读取网页，不发消息。命令返回新增数及无法匹配的行；未知状态保持未知，不把“没看到已读”改写成“未读”。

## 尚未落地的阶段

- P1：漏斗、指标、切片与区间；当前没有评测契约和 CLI。
- P2：显著变化、诊断与上下文包；当前没有服务入口。
- P3：提案、人工审批、实验分配、效果复核与经验记忆。
- P4：在线简历版本提案、上线、回读核对、条件回滚和收口。

迁移 0010 中的 `harness_versions` 已由草稿流程留存规则版本；`profile_snapshots`、`profile_versions` 已支持只读抓取结果的本地保存与版本查询，不能据此调用平台上线或回滚。P0 上线后先积累两周基线；缺回执、样本不成熟或不可观测时，不生成归因结论。设计中的“回复视为已读”属于后续度量口径，当前回执采集只记录列表明确展示的状态。

## 在线简历的规则

三站在线简历是一版通用的背景描述；按 JD 定制只做附件简历。2026-10-20 的规则允许未来通过飞轮更新公开版本，须同时满足：

1. M2 的诊断在排除数据质量、样本成熟度、平台与人群变化后，归因到在线简历层。
2. 改写走 optimizer，每条主张都有已确认证据，并完成独立复核。
3. 先展示版本差异与摘要，再由本人批准该版本；条件回滚的目标和确定性触发规则也须包含在审批内。
4. 经宿主浏览器执行，回读核对后登记版本；遇到登录、验证或风控交人。
5. 两版之间完成观察窗口，满足收口条件后锁定冠军版本。

**P4 落地前，在线简历仍保持只读。** 不用 `liepin-cli resume update-*` 零散修改，不在技能内临时实现审批或上线流程。
