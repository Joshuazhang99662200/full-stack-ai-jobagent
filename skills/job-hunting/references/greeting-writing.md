# 首条招呼写作手册（给起草模型的操作规程）

这份手册给负责起草首条招呼的模型用。规则的权威版本在 [message-generation.md](message-generation.md)「首条招呼」，那里的规则这里全部继续有效；这份手册把它们变成一步一步照做的流程。

**最重要的一条：不要自由发挥。** 候选人的话术库在 `candidate/private/greeting_style.md`。你的工作是：判断岗位类型 → 从话术库里**挑一句** → 原样拼上 → 自检。话术库里没有合适的句子时，不要自己编，把这条标成“交主会话”。

---

## 一、先弄清楚谁在读

在招聘平台上读招呼的，多数是 HR 或招聘专员，不是业务负责人。他们会在手机上扫几秒，然后决定：回不回？要不要简历？要不要转给业务看？

HR 想在这几秒里确认三件事：

| HR 想知道 | 招呼里要给出的 | 不要给的 |
|---|---|---|
| 他做过的东西和我们这个岗位是不是同一类？ | 做过什么**产品**、给**谁**用 | 你写 PRD 的方法、文档里有哪些章节 |
| 他是不是够格（级别、独当一面）？ | “从 0 到 1”“主导过”这类有分量、有证据的说法 | 职责清单、软技能自夸 |
| 做成了没有？ | 落地了、有人在用、被采用了、拿到外部认可 | 过程细节、方法论名词 |

**HR 不关心、看了会跳过的内容**：PRD 里写了交互和异常处理、验收标准、对接 API、原型验证流程、需求闭环、链路设计。这些是产品经理的日常，人人都会写，写出来等于什么都没说。只有当 JD 明确强调“要自己动手做原型 / Demo”时，才可以把“原型自己搭”作为**附加的半句**，不能作为主句。

## 二、招呼的固定结构

整条招呼只有一种结构，不允许改顺序、不允许加段落：

```
［固定开头］，［统一背书］。［产品锚点］，［一个对上 JD 的能力点］，方便聊聊吗？
```

- **产品锚点（必需）**：一句话说清候选人做过的产品是什么、能干什么。HR 先要知道“他做的是什么东西”，再看能力。锚点原文在话术库里，金融岗和非金融岗各一版，原样复制。
- **能力点**：从话术库按岗位类型挑一个，接在锚点后面，用“也……”连接。整条只讲这两件事。

- **固定开头**和**统一背书**：从话术库原样复制，一个字都不改。不加“多款”“首席”等词，不调整空格。
- **结尾**：只能是“方便聊聊吗？”，前面用逗号接上。

## 三、起草流程（严格按顺序）

### 第 1 步：判断岗位是不是该写

先看匹配档位（审批单会给出）：

- 强匹配、可能匹配、本人挑的：继续。
- 弱匹配、不匹配：**不写**，在汇报里列出原因即可。不要为了凑数写“想把这套方法用于……”这类句子，这种句子等于告诉对方“我没做过”。

### 第 2 步：判断金融还是非金融

JD 的业务或客户明确是以下任一种，就算**金融**：金融、投资、证券、基金、银行、保险、信贷、财富管理、投研、投顾。否则算**非金融**。

| 金融 | 非金融 |
|---|---|
| 可以写投资经理经历、CFA、尽调 | 不提 CFA；把“尽调”写成“报告”或“研究”，把“投资人”写成“用户”或“机构”，“创投”“一级市场”“BP”这类词都不用 |

### 第 3 步：找出 JD 最在乎的一件事

只读 JD 的“岗位职责”第一、二条和“任职要求”里最具体的一条，用一句话回答：**这个岗位最想招一个做过什么的人？**

在下面的岗位类型表里选**一个**最接近的。选不出来就选“通用 Agent 产品”。

| 岗位类型 | JD 里常见的词 | 话术库代号 |
|---|---|---|
| 通用 Agent / 智能体平台产品 | Agent 产品经理、智能体平台、企业 AI 应用、AI 产品经理 | A |
| 模型评测、算法协同 | 评测、Benchmark、模型选型、效果评估、和算法团队协作 | B |
| 文档 / 知识库 / RAG 类产品 | 知识库、RAG、长文档、检索、问答、专利、数据库 | C |
| 金融投研 / 投顾 AI 产品 | 投研、投顾、研报、金融 AI、证券 APP | D |
| 投资岗（不是产品岗） | 投资经理、战略投资、尽职调查、估值、交易 | E |
| 从 0 到 1、孵化、创新业务、要求自己动手 | 0 到 1、孵化、创新、原型、Demo、快速验证 | F |
| Prompt / Skill / Agent 架构 | 提示词、Prompt、Skill、工作流编排、Agent 架构、MCP | G |
| 行业研究、战略分析 | 行业研究、战略规划、市场分析、研究报告 | H |
| AI 质量、幻觉、可信 | 幻觉、准确率、可信、质量体系、校验 | I |

### 第 4 步：从话术库挑句子

打开 `candidate/private/greeting_style.md`，找到对应代号，按金融 / 非金融选那一句，**原样复制**。

只允许做一种改动：话术库里标了〔可替换〕的词，可以换成 JD 里的**产品类别名词**（例如把“平台产品”换成“智能客服产品”），前提是证据确实支持这个类别。其他任何改动都不允许。

### 第 5 步：拼接并自检

按第二节的结构拼起来，然后逐条回答第五节的自检题。任何一题答“否”，就回到第 4 步换一句。

### 第 6 步：交给仓库校验

所有草稿写进 drafts JSON，跑 `jobagent outreach draft-batch --candidate … --filter-context …`。被退回的，按退回原因改，**不要绕开**。

## 四、禁止清单

**禁用的词（出现即重写）**

- 过程类：闭环、链路、全流程闭环、对接 API、原型验证、PRD 里的、交互和异常处理、验收标准、需求拆解
- 咨询黑话：POC、交付、赋能、抓手、打通、场景化、方法论、颗粒度、沉淀（话术库原句里有的除外）
- 自夸：非常匹配、很适合、扎实、丰富经验、资深、顶尖、深度理解
- 套话：很感兴趣、期待交流、期待您的回复、盼复、贵司
- 打算类：想把……用于、希望能、计划、愿意尝试

**禁止的写法**

- 不写数字（只有“0 到 1”和书名号里的名称例外）。
- 不列三个以上并列名词（“RAG、Agent、多模态”这种）。
- 不复述 JD 的要求原句。
- 不重复开头已经说过的内容（开头说了“AI Agent 平台”，后面不再说“Agent 平台产品开发”）。
- 不写学校、年限、薪资、到岗时间。
- 不换行，不用括号、分号、表情。

**格式**

- 中文标点用全角（，。？）。
- 英文单词和中文之间各空一格：写“多 Agent”“AI 产品”，不写“多Agent”“AI产品”。固定开头原样复制，不受这条影响。

## 五、自检（每条草稿逐题回答“是”或“否”）

1. 开头、背书和产品锚点是不是和话术库一字不差？
2. 具体事是不是从话术库原样挑的（或只换了〔可替换〕词）？
3. 一个不懂技术的 HR 扫一眼，能不能说出“他做过什么产品、给谁用、做成了没有”？
4. 这句话换一个岗位还能原样用吗？（如果能，说明没对准，重选。例外：同一类型的岗位可以用同一句。）
5. 有没有出现第四节的任何禁用词？（应答“否”）
6. 非金融岗位里有没有 CFA、尽调、投资人、一级市场？（应答“否”）
7. 大声念一遍，每个动词后面是不是都有宾语、句子通顺？
8. 总长度是不是在 120 字以内？
9. 这条招呼里的每一句，是不是都能指出对应的证据编号？

---

## 六、输出格式（给审批单用）

每条按下面的格式列给用户，用户要能对着 JD 判断：

```
N. 平台 · 公司｜职位｜薪资｜档位｜金融/非金融｜岗位类型代号
   JD 核心：<从 JD 逐字摘一两句最核心的原文>
   招呼：<完整原文>
   依据：<证据编号>
```

## 七、对照示例（虚构候选人 Alex，展示好坏差别）

| 差 | 为什么差 | 好 |
|---|---|---|
| 我把业务需求拆成 PRD 里的交互、异常处理和验收标准，再对接 API 做原型验证 | 讲的是产品经理日常流程，HR 读不出做过什么产品 | 我从 0 到 1 做过企业知识库问答产品，已经在几家客户里用起来 |
| 我从立项起自己闭环需求、PRD 和可运行原型，推动 Agent 产品从 0 到 1 落地 | “闭环”“PRD”“原型”全是过程词；“推动落地”没说落地给谁 | 我在早期团队从 0 到 1 做出 Agent 产品并交给真实用户使用 |
| 做和多 Agent 协作，深入投资领域与协同办公场景，从 POC 跟到客户交付 | 病句；关键词堆砌；咨询黑话 | 我主导过多 Agent 协同的产品架构，已经在客户业务里跑起来 |
| 我把真实任务做成可复用 Skill，想把这套方法用于 C 端首次跑通体验 | “想把……用于”暴露没做过；弱匹配不该写 | （弱匹配：不写） |
