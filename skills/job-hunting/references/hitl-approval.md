# 人工审批与审计

准备一个 `ApplicationPackage`,内含完整职位信息、可获取时的招聘方信息、匹配报告、简历变体、diff、消息与风险项。

审批把人的身份与时间戳,绑定到当次确切的职位、简历、消息与策略摘要上。任何一处变更都会使审批失效。预览绝不意味着审批;审批绝不意味着投递。

批量流程依次是:兼容性提案、用户选择、批量预览、人工审批、顺序投递、审计。遇到登录、CAPTCHA、验证、风控或平台变更时立即停止。

## 审批必须由人在交互终端给出

`--confirm` 只是一个标志,自动调用方自己就能打上去。因此 `jobagent applications approve` **另外要求一个可交互终端**,并要求把命令打印出来的确认码原样敲回——确认码由本次产物派生,所以「批准」意味着确实看过要批准的东西。

自动调用方没有 TTY,因此无法通过这道门。这正是平台工具对自己的授权步骤采用同样做法的原因。

**这道门的边界要说清楚**:它拦住的是**驱动 CLI** 的智能体,拦不住直接 import `ApplicationApprovalService` 的调用方。人的边界在 CLI,不在库。把这一点写明,好过假装库层也安全——测试正是通过服务层铸审批的。

## 演练用 `--dry-run`

`jobagent applications send --dry-run` 走完**同样的门禁**(审批时效、变体校验、连接器解析),打印将要投递的内容,然后停在平台调用之前。它不写审计记录,因为没有发生任何尝试。

跳过门禁的演练会对一份根本投不出去的包报告绿色结果,所以演练必须跑真门禁。交互测试请默认用它。
