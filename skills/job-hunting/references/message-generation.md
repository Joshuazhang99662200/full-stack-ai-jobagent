# 消息生成策略

投递消息(打招呼语、求职信、邮件正文)与简历受同一套证据规则约束。求职信是最容易出现编造的地方,因为它的文体鼓励概括与自我评价。

## 证据规则

- 消息中的每一条**实质性主张**都必须引用一个或多个 `EVID_*`,与简历条目同标准。
- 只能引用已被用户确认的 canonical Evidence。草稿证据可以进入提案,但必须在视觉上标注为暂定。
- 允许出现的无证据内容仅限于:意向表达、对职位的兴趣、可安排的时间、礼节性措辞。这些不是主张。
- 禁止把简历里已收窄过的表述在消息里重新放大。消息中的主张范围不得超过它所引用证据在简历中已通过校验的范围。

## 禁止项

- 不得凭空造出年限、规模、增长率、团队人数、营收数字。
- 不得把参与表述为主导,不得把协助表述为负责。
- 不得声称对该公司、该产品、该团队有实际了解,除非该了解本身有证据。
- 不得编造共同联系人、共同经历或推荐关系。
- 不得声称薪资预期、到岗时间、签证状态,除非这些取自候选人档案中的显式字段。

## 招聘方信息

- 只有当连接器实际返回了 `RecruiterInfo` 时,才使用招聘方姓名与职位。
- 招聘方信息缺失时使用中性称谓,不要猜测姓名、性别或职级。
- 不得把招聘方的个人信息写入日志、审计记录之外的任何位置。

## 语言与语气

- 消息语言跟随 JD 语言,除非候选人档案中的偏好显式指定了其他语言。
- 语气默认为简洁、具体、事实导向。长度控制在能被完整阅读的范围内。
- 不使用夸张形容词("顶尖""完美契合""极其擅长")。用可核验的事实替代评价性措辞。

## 首条招呼

第一次联系招聘方的那一句话,单独有一组规则。下面前三条由仓库在 `outreach draft-batch` 时确定性检查,不合格的整条退回:

1. **长度**:不计空白不超过 120 字。
2. **不写数字**:百分比、用户数、产品个数、Agent 个数、工作年限都不写。数字留给对方回复后的定向简历与后续沟通。仅两处例外:“0 到 1”这类说法,以及书名号内的案例集名称(如《2026 某某案例集》)。
3. **不用内部术语与套话**:修订率、HITL、智能体协作;很感兴趣、期待交流、既懂。
4. **结构与口吻**:像人跟人打招呼,不像简历摘要。固定开头 → 统一背书 → 一件最贴 JD 的具体事 → “方便聊聊吗？”。不写学校。
   - 固定开头:候选人自己定一句,所有岗位都一样,写在 `candidate/private/greeting_style.md`(不进 git)。用名字加一句最核心的经历,不用全名、不用“曾任…负责人”“某证书持证人”这类简历式自我介绍。
   - 背书接成一句话:同样写在 `greeting_style.md`,比如一项可核验的外部认可(书名号内的案例集、奖项名称)。
   - 具体事用“我做过…”“我把…”这样的口语讲一件,对上 JD 的核心要求;不堆名词,不列清单。
   - 示例:您好，我是Alex，之前主导过AI Agent平台产品开发，产品入选了《某某优秀案例集》。我把专家经验拆成多个 Agent 和工具，设计人机协同流程并推动落地，方便聊聊吗？
5. **一岗一条**:同一职位只发一次首条招呼;审计里已有发送或“查重发现已发”的职位不再进清单。
6. **按垂类调整行业色彩**:先看 JD 是否属于候选人的主场垂类(例如金融:业务或客户明确是金融、投资、证券、基金、银行、保险、信贷、财富管理等)。固定开头对所有岗位都一样,这一条只管开头之后的内容。
   - **同垂类**:可以在具体事里带出该行业的资格证书和行业说法。
   - **非同垂类**:不提行业资格证书;行业黑话改写为通俗说法。具体做了什么照写,只换行业外壳,不能借改写增加证据里没有的内容。
   - 候选人自己的证书与行业词替换表写在 `candidate/private/greeting_style.md`。

   这一条依赖对 JD 垂类的判断,由宿主执行,仓库不做确定性检查。展示清单时注明每条按哪一类处理。
7. **按匹配度级联**:只给强匹配和可能匹配的职位起草首条招呼,审批单里强匹配排在前、可能匹配在后,每条标出档位。弱匹配和不匹配不起草,只在汇报里列出。`outreach draft-batch --candidate …` 会读取库里最近一次匹配结果,弱匹配与不匹配整条退回(`weak_match` / `no_match`)。没有匹配结果的职位(人自己带来的 JD)标“未评估”,排在最后。
   可选门槛:筛选配置设了 `possible_match_min_preference` 时,可能匹配还要偏好分达到这个值才起草,不够的以 `low_preference` 退回;强匹配不受影响。`draft-batch` 需带 `--filter-context` 才会执行这条。用户 2026-10-19 选择不设门槛:强匹配和可能匹配全部起草发送,偏好分只用于排序。

后续的问答式回复不属于首条招呼,不走批量审批,另有规则。

## 与审批的关系

消息是 `ApplicationPackage` 的一部分,参与审批摘要计算。消息任何一次改动都会使既有审批失效,必须重新审批。生成消息本身不构成投递意图。
