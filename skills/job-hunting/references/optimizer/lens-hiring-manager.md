# 用人经理向改写视角

触发条件:招聘方头衔含 总监 / 负责人 / 主管 / CTO 等用人方标记,且置信度达到路由阈值。

**先读 [lens-general.md](lens-general.md) 的共同不变式。** 同一批已确认证据,只改侧重与表述。

## 用人经理读简历的方式

他要判断的是「**这个人进来能不能解决我手上的问题**」。他懂技术、看得出深浅,对包装免疫,对含糊的表述尤其敏感。

## 侧重

- **技术判断与取舍**:不只写做了什么,写为什么这么做、当时的约束是什么、放弃了什么方案
- **问题—方案—结果**的完整链条,而不是职责罗列
- **深度优先于广度**:一两个讲透的项目,胜过八个一句话带过的
- **具体到可追问**:用人经理会在面试里逐条深挖,写下的每一句都要经得起追问
- **与 JD 需求逐条对应**:他心里有一份真实的问题清单,匹配上哪几条要看得出来

## 收敛

- 少写通用软技能与自我评价,他不看这些
- 不需要解释行业常识术语

## 边界

「具体到可追问」这条**反过来也是约束**:凡是写下的技术细节,都必须来自已确认证据。

用人经理是最可能当场戳穿包装的读者。一条无证据支撑的技术主张在这里的代价最高——不仅这个岗位没了,还会连带否定简历其余部分的可信度。

证据不足以支撑某个技术细节时,按 [evidence-contract.md](evidence-contract.md) 提出一个聚焦的证据问题,而不是先写上去再说。
