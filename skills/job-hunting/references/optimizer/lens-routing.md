# 改写视角路由

视角由**取回阶段实际观测到的东西**决定,不是让人挑一个,也不是让模型猜一个。

## 路由是 skill 内置的,不外挂

来源(source)是数据,可以由使用者放一份 YAML 插进来;**视角与路由不是**。

一个视角决定简历变体强调什么。若允许外部塞入视角,就等于允许绕过 [evidence-contract.md](evidence-contract.md) 与 [quality-gates.md](quality-gates.md)——一条"强调冲击力"的外部视角可以悄悄把质量门禁架空。判断力是这个 skill 的本体,必须留在内部。

## 输入只有一个来源

路由只消费**前面阶段已经观测到的结果**,不新增观测、不额外请求:

- `RecruiterInfo.type` 与 `type_confidence`(来自详情页取回)
- `type_signals`(产生该分类的具体信号,用于事后复核)

招聘方类型是本项目唯一被允许影响产物的推断属性,因此路由**门控在置信度上**,而不是直接信任标签。判定细则见 [liepin-listings.md](../liepin-listings.md)。

## 判定表

| 观测 | 视角 | 说明 |
|---|---|---|
| 无招聘方 | `general` | 没有可依据的东西 |
| `headhunter` 且达阈值 | `headhunter` | 通常来自平台自己的「猎头」标注 |
| `hr` 且达阈值 | `internal_hr` | 头衔含 HR / 人力资源 / 招聘 |
| `hiring_manager` 且达阈值 | `hiring_manager` | 头衔含 总监 / 负责人 / CTO |
| `internal_unspecified` | `general` | **诚实的非答案**:证明了是用人单位一方,却证明不了是 HR 还是用人经理 |
| `unknown` | `general` | 无任何信号 |
| 有倾向但低于阈值 | `general` | 同时记录 `declined_lens`,供人复核 |

回退到 `general` **不是降级**。在一个虚构的招聘方画像上改写,比不区分画像更糟。

## 渐进加载

路由只给出**被选中那一条**的 `policy_path`,由调用方加载该 L1 正文。不预加载其余三条,也不把正文内联进路由结果——这正是 [prompt-routing.md](prompt-routing.md) 描述的 L2 加载规则。

## 跨视角不变式

四个视角共用同一批已确认证据。视角只改变**侧重、排序与表述**,绝不改变事实。

给猎头强调规模与可转岗性、给用人经理强调技术取舍,都必须能追溯到**同一批 `EVID_*`**。某个视角"需要"一条简历里没有的证据时,该条主张就不写,并提出一个聚焦的证据问题。

无证据支撑的主张、无支撑的指标、被证据反驳的主张、语义夸大,在任何视角下依旧是 `= 0`。**视角不是放宽门禁的理由。**

## 路由结果要能被复核

每一次路由都产出 `lens`、`policy_path`、`reason`、`signals`,必要时还有 `declined_lens`。一个改写变体事后必须能回答"为什么用了这个视角",否则无法审计。
