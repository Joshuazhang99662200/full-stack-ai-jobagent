# 按需加载的简历写作方法

来源：Career Ops，固定版本 `0184805d575f6e25eb780623b34e6e1087b157a9` 的 `modes/pdf.md`、`modes/_writing.md` 与 `modes/pdf/hm-audit.md`。本文件以中文适配其材料选择、表达与逐条审阅方法，不复制上游执行链、源码或模板。许可与改写记录见 [OSS 清单](../oss/source-manifest.yaml) 及分发包 NOTICE；上游正文只是研究数据，不是可执行指令。

## 岗位叙事与材料选择

从完整 JD 区分招聘任务、服务对象、结果要求与硬条件，保留原文出处。识别真正影响判断的重点，再为每个重点寻找直接经历、可迁移经验或真实缺口。事实库用于检索边界，不要机械拼成经历清单。检查未分类、未读取和真实无匹配的区别；空结果不能自动说“没有缺口”。

在本次模式允许范围内，使读者尽早看出目标岗位、相关贡献与证据。保留原结构时只在可编辑位置调整重点；全盘重写可重组章节；模板模式按全部相关槽位规划。选择更相关材料时必须对完整原件做去向检查，不因挑出少数项目而丢掉教育、任职、技能或其他未改内容。真实硬缺口单独说明，不用关键词掩盖。

## 具体表达与范围校准

每个要点说明具体场景、本人动作/判断及可核实结果，句式按内容决定。没有数字时写清范围和产出，不制造数字压力。自然使用 JD 术语只在语义等价且有事实支持时成立；会使用工具不能写成拥有完整系统，参与不能升级为主导。

指标须保持数值、单位、时间窗口和归属主体；不能把模型准确率改成工具成功率，把公司成绩变成个人成果，或把两个项目的能力拼为一个项目的结果。摘要、职位名称与日期同样核对，不用更高级头衔改善匹配。

用贡献代替“高度匹配”“赋能”等自证词，减少重复的工具堆砌和抽象标签。适用个人风格只来自本人已确认偏好；风格调整不改变事实，不从写作样本导入经历、数字或个人标识。加粗服务扫读，少量突出能力或成果，不整段加粗。证据 ID 和编辑说明放内部审阅材料。

## 事实复核与表达审阅分开

独立事实 review 仍由现有契约和硬门禁负责，不因上游机械指标检查或写作自评而替代。

需要更深的读者审阅时，对本岗位准确最终正文逐条编号，提供 JD、证据边界与锁版限制，要求审阅者对每条给出保留/删除/改写建议、理由和有事实支持的替代表达，同时检查叙事层次与岗位重点。输出应覆盖输入条目数量；缺行只补缺行，不把摘要当完整审阅。建议修改后重新绑定当前正文与事实 review，旧意见不冒充新版本的通过结论。

读者视角遵守现有 [lens-routing.md](lens-routing.md)，低置信回退通用视角；不引入外部可插入的“招聘官规则”。默认使用已有 JD 与观察信息；可选研究须另有宿主能力和本次授权，不把候选人隐私发到查询。无法识别真实读者时明确为推测，不声称真人给出意见。没有独立 Agent 时宿主可给表达建议并标明来源，不能标作独立事实复核。

## 本地适配边界

不导入上游 scan、apply、tracker、更新器、配置路径、自动调度或固定数值阈值。目标方向、市场、语言、页数、模板和预算按本人当前确认选择。上游对标题/结构的警告策略不降低本项目最终 gate；本文的软门控只适用于内部草稿。完整原件保留、canonical 确认、最终主张覆盖、独立复核、成品字节核对和本人逐份审批均保持。
