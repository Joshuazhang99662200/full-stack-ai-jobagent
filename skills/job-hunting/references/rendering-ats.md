# 渲染与 ATS 策略

处理 `render` 能力、模板策略,以及关键词覆盖度的正向定义时,使用本上下文。

## 默认渲染器:resume-builder

排版与出 PDF 默认路由到 [resume-builder](https://github.com/StoneLL1/resume-builder)(MIT)。它是一个独立的 Agent Skill,提供中文简历模板选型、XeLaTeX 单页编译与写作手艺(量化公式、STAR、加粗关键词、每条 ≤ 2 行、经历排序优先级)。这些是本项目此前完全没有的能力。

它是**下游消费者**,不是改写器。职责切分:

| 阶段 | 归属 |
|---|---|
| 证据确认、JD 需求拆解、视角路由、内容改写、蕴含校验 | **本项目** |
| 模板选型、版式、XeLaTeX 编译、单页收敛、出 PDF | **resume-builder** |

### 边界

- **它的 `claim-map` 不替代本项目的证据契约。** 两者不是同一个轴:`claim-map` 记录"这条信息有没有出处、用户确认没有",约等于 Candidate Core 的证据确认状态;本项目的 `SUPPORTED / PARTIALLY_SUPPORTED / UNSUPPORTED / CONTRADICTED` 记录"写出来的这句话是否被它引用的那条证据蕴含"。**蕴含校验它没有,必须仍在本项目一侧执行**,不得因为已有 claim-map 而跳过。
- 交给它渲染的内容,必须是**已通过本项目校验**的变体。它负责怎么排,不负责写什么。
- 它的「重包装」口径比 [evidence-policy.md](evidence-policy.md) 的「不扩大语义」略松;以本项目口径为准。
- 它的「裸描述 ≈ 没写、引导给数字」会制造出数字的压力。本项目的 `无证据支撑的指标 = 0` 是硬门禁:**没有数字就留白**,不得为满足其写作偏好而估算。
- 它自带 PDF 解析与信息收集流程;本项目已由 `candidate ingest` 承担,不重复走它那一步。

其余上游复用边界见 [oss/resume-builder.md](oss/resume-builder.md)。

## 排版约束(ATS 安全)

简历要先能被机器正确读出,再谈美观。生成任何最终稿时遵守:

- 单栏正文。不使用多栏分栏排版。
- 不把正文放进表格。表格单元格的阅读顺序在解析器之间不一致。
- 不把任何正文信息放进页眉、页脚或文本框。联系方式必须出现在正文首屏。
- 不使用图片承载文字,不使用图标代替文字标签。
- 章节标题使用常规词汇(工作经历、项目经历、教育背景、技能),不要用创意标题。
- 日期格式在全文内保持一致,推荐 `YYYY.MM`,区间用连字符。
- 字体使用常见无衬线或衬线字体,正文字号不小于 10pt。
- 页数默认上限:十年以内经验一页,十年以上两页。超出必须先删减而不是缩字号。
- 选模板时优先单栏、无表格、无照片(resume-builder 的 `billryan` / `luooofan` 属此类);双栏高密度模板会被解析器读错顺序。

## 输出格式

- 交付格式默认 PDF,并同时保留可编辑源文件,便于后续变体复用。
- 文件名不得包含候选人手机号、身份证号或住址。推荐 `姓名_目标岗位_版本.pdf`。
- 生成物落在 `candidate/variants/` 下,该路径已被 gitignore。不要写入仓库其他位置。

## 关键词覆盖度的正向定义

`KeywordCoverageReport` 度量的是"JD 关键词是否已被有证据支撑的表述覆盖",不是"关键词出现了几次"。

- 一个关键词只有出现在**已通过校验的实质性主张句内**时,才计入覆盖。
- 独立的技能堆砌区、关键词罗列段、白色隐藏文字**一律不计入覆盖**,并且禁止生成。
- 同义词与缩写按 JD 的写法归一(例如 JD 写 `K8s` 就用 `K8s`),但归一化不得改变主张的语义范围。
- 未被覆盖的关键词报告为缺口,并可触发一个面试问题;不得通过塞词消除缺口。

关键词或 ATS 目标绝不凌驾于事实接地之上。当提高覆盖度的唯一办法是编造或放大主张时,正确做法是保留缺口。

## 校验

渲染完成后重新校验:正文是否可被文本抽取还原、抽取结果的阅读顺序是否与视觉顺序一致、页数是否超限。任何一项不通过,返回渲染校验失败,不要交付。
