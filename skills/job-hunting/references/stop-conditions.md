# 停止条件

全流程中需要停下来交给人的时刻集中在这里。停止不是失败;继续推进才是。

## 必须停止并等待人的情形

| 触发 | 处理 |
|---|---|
| 候选人就绪度不足以支撑目标岗位 | 停止寻源,先补面试与证据 |
| 硬过滤返回 `REVIEW` | 保留 `REVIEW` 状态直到人做出判断;绝不静默放行 |
| 需求映射返回 `MISSING_EVIDENCE` | 停止该条主张的改写,提出一个聚焦的证据问题 |
| 校验返回 `UNSUPPORTED` 或 `CONTRADICTED` | 撤回该主张;不得用放宽后的指令重试 |
| 校验返回 `PARTIALLY_SUPPORTED` | 收窄表述并重新校验;仍不通过则撤回 |
| 质量门禁任一项未达标 | 不交付该变体 |
| 渲染校验失败(抽取顺序错乱、超页) | 不交付,先修排版 |
| 审批摘要与当前产物不一致 | 投递失败并报"审批已过期",要求重新审批 |
| 连接器返回 `USER_INTERVENTION_REQUIRED` | 停止;由人在平台上完成操作后,再显式发起下一次 |
| 需要调用"仅契约"或"未开始"的能力 | 停止;说明该步骤尚未自动化,产出经人工评审的类型化 JSON 交接 |

## 不构成重试理由的状态

登录、CAPTCHA、验证、风控与平台变更**不是**瞬时故障。不要自动重试,不要更换账号或代理绕开,不要降低请求间隔试探。这些状态一律翻译为 `USER_INTERVENTION_REQUIRED` 并交还控制权。

只有提供方明确声明为暂时性的传输故障才可以重试,且最多一次。结构化输出格式错误可以尝试一次修复。

## 停止时要输出什么

停止时给出:触发了哪一条停止条件、当前已完成到哪一步、恢复需要人做什么、以及恢复后从哪个能力继续。不要在停止的同时抛弃已经通过校验的中间产物。
